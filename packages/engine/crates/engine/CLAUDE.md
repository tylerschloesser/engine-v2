# engine crate (Rust side)

The crate game authors path-depend on; it and the game crate compile into one WASM module. It ships inside the npm package (`files` lists `crates`).

## Workspace

A member of the root cargo workspace. These live at the repo root, not here: profiles and `[workspace.lints]` (`Cargo.toml`), the clippy ban lists (`clippy.toml`, owned by `docs/decisions/0002-determinism-same-wasm-everywhere.md` §3), the toolchain pin (`rust-toolchain.toml`), nextest profiles (`.config/nextest.toml`). This crate's `Cargo.toml` inherits `version`, `edition`, `publish` and `lints` from the workspace.

`[profile.dev.package."*"]` covers only non-member dependencies, so this crate builds at the dev `opt-level` (0024 §13).

## Commands

- `pnpm test rust [-t <name>]`: nextest over the workspace; `-t` is a substring of the test name. Raw `cargo nextest run` and `cargo test` also work.
- `pnpm lint` runs `cargo fmt --check` and `cargo clippy --workspace --all-targets -- -D warnings`. `pnpm format` fixes formatting.
- On macOS, native linking needs `DEVELOPER_DIR` when the Xcode licence is not accepted; the scripts set it (`scripts/lib/env.mjs`). For a bare `cargo` call that links: `DEVELOPER_DIR=/Library/Developer/CommandLineTools cargo …`.

## Layout

- `src/abi/`: the JS↔WASM boundary (0014). `registry.rs` is the single owner of the ABI and states the rule for adding to it; `mod.rs` holds what the exports do; `boot.rs`, `regions.rs`, `arena.rs`, `panic.rs`, `config.rs` are the pieces. `panic::fatal` exists because std formats a panic message into a `String` before the hook runs: use it, not `panic!`, anywhere the allocator may be the failure. Sim exports (docs/plan/13-sim-host-tick-loop.md, docs/plan/15b-ring-connection-and-replica-rendering.md): `sim_genesis() -> status` (builds the world from the init config; M22b adds the load path), `sim_seal_frame() -> len` (write-ahead log bytes into `RegionId::Persist`; always 0 until M22), `sim_warm_one() -> u32` (1/0, the warmer's between-tick chunk generator), `tick_hz() -> u32` (the sim role's real tick rate, `20` default, `Host<G>`/`GameInstance<G>` overriding it as `G::TICK_RATE.hz_value()` -- `SimHost`, `packages/engine/src/server.ts`, reads it once at construction instead of assuming 20); `sim_connect(conn) -> status`/`sim_disconnect(conn) -> status` (M15b: `host::Host::connect`/`disconnect`); `sim_tick`/`sim_hash`/`sim_admit(conn, len)`/`sim_build_frame(conn) -> len` are all real once a role-`Sim` `Instance` exists (M15b routes the last two, plus `sim_tick`, through `Host`'s connection-aware `tick`/`build_frame`/`seal`, not the bare `Sim::step` M13 left them at). `ABI_VERSION` is 10 (M15b steps 4-6 added the client-role `on_frame(len) -> status`/`client_poll_uplink(t_ms) -> len` pair, `RegionId::Downlink`, and the test-only `sim_region_hash`/`client_region_hash`/`sim_conn_counters`).
- `src/host/` (M13, connections M15, ABI-real M15b): `Host<G>` -- the sim-role `Instance` (`Sim<G>` plus `sim_genesis`/`sim_seal_frame`/`sim_warm_one`'s own state) plus a fixed connection table (`connect`/`disconnect`/`on_uplink`/`tick`/`seal`/`build_frame`/`region_hash`), and `host::warm::Warm` (the between-tick warmer: a fixed-capacity per-connection view list, `set_view`/`warm_one` over `view::nearest_first` -- `build_frame` feeds it a real subscribed rect every call). `host::subs::SubscriptionSet` (M15, 0010): ring-1-plus-look-ahead subscription, hysteresis, the 128-chunk cap. `src/client/` (M15, docs/plan/15-connection-and-subscriptions.md): `client::Replica<G>` (the replicated state a client holds: `Store<G>` + held-chunk versions, `WorldRead<G>` directly, `Unknown` outside the held set) and `client::ClientCore<G>` (`on_frame` decodes a frame twice -- once to validate, once to apply, so a malformed tail never mutates the replica -- `poll_uplink` paces the uplink per 0010 "Rates"). **`host/` and `client/` are outside the deterministic core: they may read subscriptions and cameras; `sim/` (`sim.rs`, `authority.rs`, `store.rs`, `world/`, `worldgen/`, ...) may not import them** -- enforced by `tests/module_layering.rs`. `src/game_instance.rs` (M13): `GameInstance<G>`, the `Instance` `export_game!` now points at -- dispatches `Role::Sim` to `Host<G>`, `Role::Gen` to `worldgen::GenCore<G::Worldgen>`, `Role::Client` to `ClientInstance<G>` (a generic `TerrainStore`/`TerrainFeed`/`Uploader`/`InputQueue` assembly; existing fixtures with their own hand-written `Instance` impls, `fixtures/terrain` and `fixtures/worldgen`, are untouched). `Host::init` declares the sim role's own `Rx`/`Tx` regions now (M15b: `SIM_RX_BYTES` 4,096, `SIM_TX_BYTES` 65,536, both provisional -- 0010's own bandwidth/backpressure budget for them is Non-scope, M31). `ClientInstance<G>` (M15b steps 4-6) now holds a boxed `client::ClientCore<G>` instead of its own standalone `TerrainStore`: `Replica<G>`'s own store is the one `TerrainFeed`/`Uploader` share too (`Replica::terrain`/`terrain_mut`, `pub(crate)`), so `on_frame`'s dispatch can drain `Replica`'s dirty queue (`client::DirtyEvent::{Whole, Tile}`, one `Vec`, not two -- a first attempt with two separate queues reintroduced the exact unbounded-growth bug M15 fixed for cache events, since only one of `drain_dirty`/`drain_dirty_for_upload` is ever called per instance) straight into `Uploader::enqueue_chunk`/`patch_tile`.
- `src/hash.rs`: `Fnv64`. `src/testing/` (feature `testing`, dev-dependencies only): `golden_bytes` (`assert_golden`, `assert_golden_bytes!`/`assert_golden_hash!`), `cache_matrix` (below), `testkit` (`run_script`: drives a `Sim<G>` through a `(Tick, Record)` script, idling any gap, returns the final `state_hash`; `Loopback<G>`, M15: one `Host`, `K` `ClientCore`s, real wire bytes end to end, each client behind its own constant tick delay -- freely imports both `host` and `client`, unlike the deterministic core), `budgets` (M15: `budget`/`expect_within_budget`, the Rust-side reader for `packages/engine/budgets.json`, mirroring `tests/support/budgets.ts`).
- `src/world/` (0007): `tile.rs`/`coords.rs`/`traits.rs` are plain data; `overlay.rs` is the sparse per-chunk state (`ChunkOverlay`, `Overlays`); `cache.rs` is the dense LRU slab pool (`CacheCapacity`/`CacheEvent` are its only public seam); `terrain.rs`'s `TerrainStore` composes them. **The cache is not state**: never serialized, hashed, or part of `modified_tiles`; `TerrainStore::tile`/`materialize` take `&self` (a `RefCell` inside) because a read may generate and evict. No method here returns a reference into a slab -- reads return `Tile` by value, `copy_chunk` copies out.
- Adding or changing anything that touches the cache: prove invisibility with `engine::testing::assert_cache_invisible(|cfg| { .. build a store at cfg.capacity, prewarm with cfg.prewarm, run a script, return checkpoints .. })` (feature `testing`) -- it replays your closure at capacity 1, the default and `Unlimited`, crossed with three prewarm orders, and fails if any leg's checkpoints differ. `world_cache_invisible.rs`'s `cache_invisible_matrix` is the reference caller.
- `src/game.rs` (0003, M12): the `Game` trait, ids (`PlayerId`, `EntityId`), `Unknown`, `PlayerEvent`, `OldStore`/`SaveIncompatible` shells (still M24b's to fill), and `pub use` re-exports of `WorldRead`/`WorldWrite` (`src/world_access.rs`), `TickCx` (`src/authority.rs`), `FrameCx`/`FrameView`/`DrawList` (`src/client/`) and `Presence`/`PresenceTable` (`src/presence.rs`, M19) so every caller's `crate::game::{WorldRead, WorldWrite, TickCx, Presence, PresenceTable, ...}` import path stays the same regardless of which module actually defines them. `src/presence.rs` (M19, docs/plan/19-presence-channel.md steps 1-3): `Presence`/`PresenceEntry`/`PresenceTable<G>` (`get`/`iter` public, `on_sample`/`remove`/`restore` engine-internal by convention -- a compile-fail doc test on `PresenceTable` proves `Game::apply`'s own signature cannot name it). **Presence types never enter `Store`, the log or a hash**: `apply`/`tick` have no `PresenceTable` parameter at all, so the deterministic core has no way to read one even if it wanted to. `src/time.rs`: `Tick`, `Ticks`, `TickRate` (the 0006 conversions -- `hz`/`millis`/`secs`/`dt` -- are M12b's). `src/rng.rs`: `SimRng` (hand-rolled PCG32, 0002 "Randomness"). `src/delta.rs`: the engine-defined `Delta<G>` (0011, plus the engine-only `Roster` and `Ack` variants of 0024 §8 and M12b respectively -- `Ack` is never rebroadcast to a client, see `authority.rs`). `src/store/mod.rs` (M12, M21): `Store<G>` -- tile overlays (`TerrainStore`), entities, players, global, and (M21) the `Registry` `Game::register` fills once at construction plus every chunk's `ChunkIndex` -- whose only mutator is `apply(&Delta<G>)`; canonical `encode`/`decode` and `impl StateHash`. **`store/index.rs`'s `ChunkIndex` (occupancy bitset + sorted `(index, EntityId)` + overlapping ids) is derived, never encoded or hashed** (0007 §5): maintained incrementally by `Store::apply`'s `EntityPut`/`EntityGone` arms, rebuilt from the entity table by `Store::rebuild_indexes` (called automatically at the end of `decode`) -- the same derived/state split `world/cache.rs`'s own dense slabs already draw. `src/budget.rs` (M21): the state-budget check + growth-honesty audit (0004, 0023), called from `Sim::step` -- deliberately *not* under `host/`, since `sim.rs` may not import it (`tests/module_layering.rs`).
- `src/world_access.rs` (0003, M12b): `WorldRead`/`WorldWrite`, filled in exactly as 0003 (object-safe, trait-object upcasting); `View`, the read-only host/replica context (a "held chunk" predicate, always true on the host). `src/authority.rs` (M12b): `Authority<G>` (`Store` + `SimRng` + `Tick`, since M12's `Store` deliberately holds neither), `Scope`/`Scopes`/`ChangeLog` (scope derivation at write time), and `TickCx` (minimal: `as_write`/`player_count`/`player_id_at`; M21b adds wake/timer/active-list methods). `src/sim.rs` (M12b): `Sim<G>`, the host driver -- `genesis` builds a fresh world and runs `Game::genesis` once; `step` runs one frame's records in 0004 order, then `Game::tick`, then advances the tick. **The two author rules from 0003** ("validate first, write after" and "copy-modify-put; add a `?` to each read and `impl From<Unknown> for Reject`") aren't just prose here: the first is a runtime assert in `Sim::step` (`a rejecting apply recorded a write` panics if a rejected `Game::apply` pushed any change onto the `Authority`'s `ChangeLog`), proven both ways by `fx-puts`'s `tests/puts_apply_contract.rs` (a clean reject, and a deliberately bad test-only game that writes then rejects).
- `src/client/drawlist.rs` (M17, 0018 §2; docs/plan/18-picking-and-overlay.md steps 4-6 add `anchor`/`ANCHOR_SLOTS` and `sort_into`'s own `follow` parameter): `Draw`/`DrawList` -- the per-frame draw list `ClientSide::extract` fills through builder methods (`sprite`/`circle`/`ring`/`rect`/`bar`/`radial`/`ghost`/`anchor`), counting-sorted by `layer` into a `RegionId::DrawList`-shaped buffer by `sort_into` (`game_instance.rs`'s own follow-up call inside `frame()`, not part of the game-facing surface), which also writes the header's `follow_valid`/`follow` (absolute world tiles) and `anchor_mask`/`anchors` (tiles relative to `window_origin`, like `Draw::pos`) fields. **`extract` is pure over `FrameView`: iterate `entities()`, never allocate; positions are `WorldPos`, the engine subtracts the window origin.** `src/client/frame_view.rs`: `FrameView`/`Clocks`/`EntityIter` (M16b's minimal shape, grown by M17 with `entities()`, `visible()`, `zoom()`, `px_per_tile()`, `cursor_tile()`, `window_origin()`, `time_ms()`). `src/client/frame_cx.rs` (docs/plan/18-picking-and-overlay.md steps 4-6): `FrameCx<'a, G>`, `ClientSide::frame`'s own per-frame context -- **`frame` mutates (`cx.follow(..)`, `cx.ui_dirty()`), `extract` reads (`&FrameView`)**; `cx.input()` is the slice of `client::input::InputEvent`s (`InputQueue::events()`) drained from `inputRing` since the previous `frame` call, oldest first, valid for that call only -- `game_instance.rs`'s `GameInstance::frame` builds one `FrameCx`, calls `G::Client::frame`, then reads back `cx`'s own `follow`/`ui_dirty` state before `extract`/`sort_into` run, and clears `InputQueue` only after all of that. `InputEvent::kind == client::input::kind::GAME` (7) is `client.input.emit(code, a, b)`'s own record (`code()`/`a()`/`b()` accessors over `pick_id`/`tile`); `InputQueue`'s overflow policy never drops an already-queued `GAME` event.
- Determinism rules for everything here: `.claude/rules/determinism.md`. `world/cache.rs` also carries `.claude/rules/hot-paths.md` (reads are per-tick).

## Tests

- Unit tests inline (`#[cfg(test)] mod tests`); scenario and replay tests in `tests/*.rs`.
- Slow tier: name the test function `slow_*`. `pnpm test` filters it out; `pnpm test:slow` runs only those.
- `tests/runner_control.rs` is the runner's permanent negative control (fails only under `pnpm test --self-check-fail`). Keep it.
- `cargo fmt --check` only sees files in a target's module tree: a stray `.rs` outside `src/` or `tests/` is never checked.
