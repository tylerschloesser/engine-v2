## Scope
- **Dedupe the forced re-put.** When a chunk's snapshot is sent to a connection, a line anchored in it that the connection already holds at its current `structure_version` (and whose list the client holds, not `unknown`) is not put again; a line not held, held at an older version, or `unknown` is put as today. The replica must keep the held structures and trajectories of a chunk across its snapshot (verify; if it clears them, the engine side of this item is the replica keeping them, and the chunk hash must still agree). Rust: `host_snapshot_does_not_reput_held_lines` (Loopback, a view whose lines are held before their chunk enters: puts counted once per line; chunk hashes agree; items exact), the lost-frame path (§20 (c)) still converges (`lost_frame_never_desyncs_a_held_chunk` green), `forecast_matches_host_under_budget` and the whole `forecast_`/`line_`/`host_` families green.
- **A stateless feeder.** `fx-belts` gains `Thing::Feeder { at, line, item }` (bench genesis only, on the `"spawner"` list): one `insert_back` attempt per tick, refusal dropped, no state, never written, declared to the tracker with `period: 256, acc: 0, kinds: 0`. A `BenchRegime::MixedFeeders` builds the `Mixed` world with feeders in place of every spawner (same lines, same items at rest; the item kind per chain as the world gives it; cycling chains get a plain feeder of their first kind). `belts_feeders_write_no_delta` (Rust: 600 ticks, the change log carries no entity delta from a feeder; `spawner_mismatches` 0).
- **Re-measure the join** (`belts/join_at_scale @slow` gains the `MixedFeeders` cell beside the `Mixed` one, both pinned): ticks and bytes by section to a fully held view at the default pacing; record in Deviations and 0078 A11 (manager). ## Planning decisions
- **A snapshot re-puts only what the client lacks.** The forced put existed so the client's chunk state and its structures arrive together (0079 §17 (a)); a client that already holds the line at the same version has the same structure the snapshot would carry, so the chunk hash agrees without it. The lost-frame rule (§20 (c)) stays correct: a line the lost frame named is already sent `Gone` and re-put by `LineRoute::lost`; a line it did not name is unchanged on the client.
- **The feeder is the reference shape.** 0079 §19 (e): a spawner that writes a delta per insert collapses chunks under production pacing; the reference game's spawners (M53) keep their schedule in the tracker's declaration and write state only when a player changes them. The feeder is that shape in the fixture.
- **No bench baseline moves.** `slow_tick_belts_large` runs the `Mixed` regime; the dedupe runs only on snapshot frames (none in the bench's steady state after warm-up): three runs at quiet load must sit within noise of 1.2638 ms.

## Deviations

Steps 1-3 (implementer, 2026-10-12; commit, tag and 0078 A11 are the manager's). Tyler's M3 Max, shared: every timing names its 1-min/5-min load.

**The replica cleared, so the engine side was built.** `ClientCore::on_frame` called `Replica::drop_anchored_structures` before every chunk snapshot (M46: a `Gone` per anchored line, items and trajectory with it), so a held line was dropped and re-put with its list. Now the replica keeps them (the call and the function are gone, `client/core.rs:1251`, `client/replica.rs` module doc); a put of a held line replaces its structure in place. `LineOp::Drop` (a forced put that did not fit, "the client already dropped it") is gone: a held line whose forced put does not fit is sent `Gone` like any held update (`host/lines.rs:563`, counted in `budget_gones`).

**The dedupe as built** (`host/lines.rs:458`, `LineRoute::holds_current` at :189): a line anchored in a chunk this frame snapshots is forced only if the connection does not hold it at its current `structure_version` or holds it `unknown`; forced puts are `fresh` (their list rides) as before. Older version and `unknown` therefore go as today (fresh, with the list or an `unknown` one); a line not held is put fresh. Collapses and §20 (c)'s lost-frame re-snapshots go through the same path: a lost frame's named lines are already in `LineRoute::lost` and go `Gone` first (`plan`'s first branch), then are re-put fresh; a line it did not name is unchanged on the client and is skipped. **Departure: a resync answer forces every anchored line.** The brief's rule alone left a corrupted structure at the current version un-repaired: `belts/structure_resync_after_corruption` (netcode) looped, 32 host desync reports against 1. `Host::on_resync` now notes the chunk in `LineRoute::resync` (`host/mod.rs:1142`, reserved at 256, never grown; a full list drops the note and the client reports again), and the snapshot that answers it forces all its anchored lines (the put overwrites the replica's copy); the note clears when that frame is sent. **Departure: the bucket prices what is sent.** The enter drain priced each snapshot with every anchored line's put and list (`StructPrices::anchored_bytes`); it now prices only the forced ones (`StructPrices::snapshot_puts_bytes`, `host/lines.rs:969`, at `host/mod.rs:2153`; counted afresh on every drain attempt, a head chunk the bucket cannot yet pay for included, beside that chunk's snapshot encode: the same order of work). Without it the dedupe saves the bytes but not the time: the `Mixed` join with the dedupe and the old price read 377 ticks (as M48b), 2,335,290 B, 1,850 lists, 178 collapses. The delta-collapse estimate (shared by every connection, every tick) still prices the full re-put: an upper bound, so it collapses no more often than before.

**The feeder and the regime.** `Thing::Feeder { at, line, item }` (appended last to `Thing`; no encoded value moved) and `BenchRegime::MixedFeeders` (appended last; marker tag 4; `world()` is `Regime::Mixed`): `bench::build` spawns one feeder per world spawner at the spawner's tile with the chain's first item (a cycling chain's first kind). A feeder's tick: one `insert_back`, the result dropped, no write; on the tick it joins the list, `set_spawner(Schedule { period: 256, acc: 0, kinds: 0, next: item })`, and `declare_spawners` declares the same after a restore. `pnpm golden belts` idempotent (no golden file moved).
