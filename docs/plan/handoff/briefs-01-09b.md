- The crate stays a single `engine` crate and is split only on one of three triggers, each with an ADR: (1) the runner's build line warns (edit to tests-starting over the 0020 §3 compile budget) in two consecutive milestones and `cargo build --timings` shows `engine` is the critical path; (2) non-sim code needs blanket `#[allow(clippy::disallowed_*)]` in more than three modules (the 0002 lint scope wants a crate boundary); (3) a proc-macro becomes unavoidable (it needs its own crate). Constraints on any split: the game-facing crate is still called `engine` and re-exports the others, every crate stays under `packages/engine/crates/` so `files` ships it. Nothing measured says the loop is slow. — source: docs/plan/01-scaffolding.md:83 — proposed home: line in packages/engine/crates/engine/CLAUDE.md (line 60 currently points at this brief "until an ADR replaces them"; replace the pointer with the triggers)
- `scripts/` runners are plain Node `.mjs` with zero dependencies and no build step, because Node's type stripping still prints an experimental warning that would break the one-line quiet output contract. `cargo-nextest` is installed globally (`~/.cargo/bin`) by `pnpm setup:tools` and never from `pnpm test` or `postinstall`: a multi-minute compile inside a test or install command breaks the output contract, and a per-repo `--root .tools` would make every agent worktree pay the compile again. — source: docs/plan/01-scaffolding.md:86-88 — proposed home: new ADR group "testing/tooling"
- `engine.log` and `engine.panic` text is decoded in the instance's own isolate by the loader (one module-level `TextDecoder`), then handed to `LoaderHooks.onLog`; it is not forwarded to main. Why: worker consoles already reach DevTools and Playwright, a server has one isolate, and a log call inside a measured window is meant to fail 0016 on the isolate that made it. This settles the 0014 deferred item. — source: docs/plan/02-build-and-determinism.md:87 — proposed home: new ADR group "runtime/packaging/hosting"
- The WASM arena owns no allocator: `abi::Arena` wraps `std::alloc::System` and `engine_init` reserves by allocating and freeing one block of `arenaBytes`, so std's allocator does the single `memory.grow`. M07 then decided the world pools need no sub-allocator on top (slab pool and index table are allocated once in `TerrainStore::new` and never resized; probe showed a 900 KiB allocation after init reuses the freed reservation, `memGrows() === 0`). Measured, not assumed; the alternative (own allocator) was rejected as more code for no observable gain. — source: docs/plan/02-build-and-determinism.md:89 and docs/plan/07-world-model-core.md:53 — proposed home: new ADR group "runtime/packaging/hosting"
- Codec design: canonical floats come from a delegating serde `Serializer` wrapper (`CanonSerializer`), not float newtypes and not a postcard `Flavor` (a flavor sees bytes, not types). Decoding is deliberately not wrapped (a delegating `Deserializer` must wrap every `Visitor`, several times the code); untrusted bytes go through `decode_canonical`, which decodes, re-encodes non-strict and rejects any difference. That re-encode is load-bearing: postcard does not police canonicality itself (it accepts overlong varints like `[0x80,0x00]`), and it must be non-strict because untrusted bytes can legitimately decode to NaN, which has to be an ordinary `NonCanonical` error, not a debug-assert crash. The state hash is the same canonical writer fed to an `Fnv64` sink instead of a `SliceSink`, so "hash = FNV-1a over canonical snapshot bytes" is true by construction. `usize` cannot be policed by serde (it arrives as `u64`), so it stays a review rule plus a source scan. — source: docs/plan/05-codec-and-state-hash.md:47-51,84,85 — proposed home: new ADR group "simulation"
- Ring full-ring policies and why (capacities are in `sab/layout.ts` `RING_DEFAULTS`, the policies and reasons are not): `downlink`/`uplink`/`uiRing`/`uploadRing`/`genRequest`/`genResult` apply backpressure; `actionRing` makes `dispatch` throw `RingFull` (human rate, 0004 burst x 1.5); `inputRing` is drop-and-count because an input event seconds old is worthless, with `drops` 0 in every test (ring.ts does not yet implement the drop, left to the input milestone). Settles the 0015 "ring capacities per link" deferred item. — source: docs/plan/06-sab-primitives-and-workers.md:46-62 and :296 — proposed home: new ADR group "runtime/packaging/hosting"
- The client worker has no clock of its own: `frame(t_ms)` takes the time from the camera block and runs only when `CB_FRAME_REQ` differs from `W_ACK`; frames never queue (a late worker serves the newest request once); a ring-producer wake without a new frame request only drains rings. This keeps the client instance free of ambient time and makes `stepFrame` exact, and resolves what 0018 deferred to 0015. The export's raw `t_ms` argument is unused: Rust reads `camera.frame_time_ms` (a `Float64Array` element read in JS boxes about 12 B per frame), which is why the export keeps its declared shape and `ABI_VERSION` did not bump. — source: docs/plan/06b-workers-and-spawn.md:56 and :261 (decision A) — proposed home: new ADR group "runtime/packaging/hosting"
- Overlay promotion to a dense chunk at 512 entries is not built in Phase 3 (reads never consult the overlay, a sorted insert moves at most a few KB, the 12 MiB overlay share already prices the worst case). It is a pure representation change behind `ChunkOverlay`, so it needs no ADR when added. Trigger to build it: M36's standard-large-save run shows overlay memory, not entities, breaking the world budget, or a game whose rules rewrite whole chunks. Bucketed per-chunk area effects are out of scope too: no reference rule is area-based, chunks do not tick (0007 §7); a game that wants them brings an ADR, natural home beside the active lists. Settles two 0007 deferred items. — source: docs/plan/07-world-model-core.md:56-57 — proposed home: new ADR group "world"
- No sampled pristine-hash check between client and server in Phase 3. Under one `.wasm` plus the handshake build hash a divergence is an engine or JIT bug, and three cheaper nets exist: the six-runtime worldgen golden, the fingerprint in saves (0007 §9), and `insert_pristine`'s debug assertion comparing gen-worker output with the instance's own generation. If a field report ever needs it, it is one more entry kind in the `Hashes` section beside the per-chunk hashes, so that entry-kind byte must stay extensible. Settles the 0008 deferred item. — source: docs/plan/08-worldgen-and-gen-worker.md:50 — proposed home: new ADR group "world"
- Terrain cache and overlays are one unit (`TerrainStore` embeds the cache; `Store<G>` embeds a `TerrainStore`), because keeping an overlay canonical needs the pristine value at write time, on the host and equally on a client replica applying `Delta::Tile`. The `RefCell` is needed because `WorldRead::tile` takes `&self` while a read may generate and evict; no reference into a slab ever escapes. Writes materialise the chunk first so the canonical check never regenerates. Only the `RefCell` part is in the crate `CLAUDE.md`. — source: docs/plan/07-world-model-core.md:50-52 — proposed home: line in packages/engine/crates/engine/CLAUDE.md (extend the "cache is not state" bullet with the why: single owner of cache and overlay so replicas stay canonical)
- Renderer tests need probes that leave texel centres. Every M09b probe sat exactly at a texel centre, the one point where the correct and incorrect magnified-sampling formulas agree, so an inverted seam formula shipped through two fix rounds with a green suite; it was found by a Sonnet review of the diff, and `terrain.seam_matches_reference` (probe at art texel (2.4, 0.5)) now guards it. The same review found flip/rotate with zero pixel coverage (`flags: []` on every fixture visual) and jitter amplitude chosen under every probe tolerance. Rule: a probe grid that never leaves texel centres cannot see a sampling bug, and every shader feature needs at least one fixture that exercises it above tolerance. Sprite sampling (M17b) reuses this seam formula, so the warning applies to any copy. — source: docs/plan/09b-terrain-art-and-lifecycle.md:691-760 and :793 — proposed home: line in packages/engine/CLAUDE.md ("Adding a browser spec" section, renderer-test bullet)
- Test pages that register a real `ResizeObserver` race the test's own forced size: the failure was load-inverted (2 in 16 quiet runs, 0 under `--load 10`) because the observer callback runs in the browser's rendering step, which heavy load delays past the test's teardown. Not a production defect (a real notification can never be stale relative to an earlier one). Diagnosed with timestamped instrumentation, not guessed. Lesson for flake triage: a flake that disappears under load may be a window that load closes, so repeat on a quiet machine too. — source: docs/plan/09b-terrain-art-and-lifecycle.md:387 — proposed home: line in .claude/skills/run-tests/SKILL.md (flake-triage section)
