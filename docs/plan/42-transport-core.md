## Planning decisions
- **Winner and settled rules from M40** ([0077](../decisions/0077-transport-item-representation.md) Amendment A6, A6b): the store is B1 (linked runs in one arena, per-line jam cursor, canonical merged form); a squashed pair across a hand-off is legal and `insert_*` check their own line only; every `count` merge guards `u16` overflow; the codec's spacing check is within a line. B2 (a contiguous ring per line) is the measured fallback if a per-call scan ever matters (A4).
- **`advance` after `G::tick`.** The game's inserts of a tick (spawners, later inserters) land before the lines move, so `insert_back` lands the item at `max(len - speed, tail + SPACING)` *before* this tick's advance and the advance then moves it: an item inserted this tick sits at `len - 2 x speed` when the tick ends (it entered one tick's travel inside the back edge, then moved), and a `Sink` line with `len < 2 x speed` sinks it the same tick, which is legal and conserved; the opposite order would make every insert account for a move it missed. One order, stated here, pinned by `spawn-to-sink`.
- **The access rule is pinned here, the request pattern in M42b.** `transport_in_apply_is_unknown` and `transport_predicting_is_unknown` prove 0076 §6 with a local test game; `fx-belts` (M42b) routes every topology change through a `Request` entity because of that rule.
- **The jam summary.** `Line::jam()` reports the position of the rearmost packed item at the front (the "jam end"), maintained by `advance` at no extra pass; M47's cheap forecast reads it for `stop`.
- **Order recompute on edit only.** A `graph_dirty` flag set by `create`/`destroy`/`set_out`; `advance` recomputes once when set. Cycle cutting at the lowest `LineId` in each strongly connected component (Tarjan, preallocated scratch sized by `max_lines`).
- **Snapshot bump, saves lost.** Existing reference-game saves become `SaveIncompatible`; the milestone's report tells Tyler (a cost, his to object to); no migration is written.

**Where the bytes sit.** The transport section is the last thing `Store::write_canonical` writes, after the wake queue. `Store::encode` always writes it; the state hash writes it only once the store is not pristine (a line was ever created, `Transport::is_pristine`), so every world that never uses transport keeps its pre-M42 hash: no `golden.json`, no `games/reference/tests/golden/full-game.json` and no fixture checkpoint hash changed. Per line: `id u32, len u32, speed u16, out (tag u8 + ids), sunk u64, jam u32, run_count u32, runs (item u16, count u16, dist u32)`, then `next_id u32` (module doc of `codec.rs`). Two departures from the brief's field list: (1) a later run's `dist` is `gap + SPACING` (the distance from the item ahead), not the in-memory `gap`, so a spacing violation is representable in bytes and decode rejects it; with raw `gap` (a `u32` of free space beyond `SPACING`) no byte pattern could violate spacing and the codec test would have nothing to reject. (2) The `jam` cursor is encoded (its run index): a re-walk from the front can merge a same-item pair the cached skip leaves unmerged (a pair refused by the `u16` guard whose front run later shrank), so a restored world must carry the cursor to advance exactly like the live one.

**Phase flag.** `Authority` already had `in_genesis`; it gains `in_tick`, set by `Sim::step` around `G::tick` only. `Authority::transport_mut` is `Ok` when either is set, else `Err(Unknown)` behind a `debug_assert!` naming 0076 §6 (so it also fires in `on_player`). `TickCx` answers `Ok` itself; `in_tick` covers a tick rule reaching `Authority` through `TickCx::as_write`. `Migrating` answers `Ok`; `Predicting` marks the overlay and answers `Err(Unknown)`.

**Caps and memory.** `Store::new` holds an empty `Transport` with no arena (a client replica and every plain test store reserve nothing). `Authority::new`/`from_snapshot` reserve 0076 §8's defaults (as they default the budget fields), and `Sim::genesis` plus every host restore/upgrade/migrate path apply `WorldParams::{max_lines, max_items}` through `Authority::set_transport_caps` beside `set_budget`: the reservation happens when the world params arrive, not literally in `Store::new` (whose signature 18 callers share). At the defaults a host world reserves about 7 MiB (nodes 16 B x 262,145 = 4 MiB, because a B1 node carries two `u32` links beside the 8-byte run; lines ~2 MiB; index, order and Tarjan scratch ~1 MiB), against 0076 §8's nominal 4 MiB; natively the reservation is lazy, in WASM it grows the sim memory at genesis, for every game. `host::Host::init`'s memory-split check does not count it. M57 owns the phone defaults.

**Scope changes.** `insert_at`/`remove_at` (0076 §3's inserter primitives, M43 in the plan) are implemented and on `TransportWrite`: 6 of M40's 20 rule cases call them, and the cases' items at rest are placed with `insert_at`. `destroy` hands its items to a callback (no `Vec`) and turns lines that fed it into `DeadEnd`; M43 owns the rest. `set_out` refuses `Merge`/`Fork` and a `Next` into the line itself with `TransportError::Unsupported`; decode refuses them too. **Order.** Tarjan emits components in reverse topological order with roots tried in ascending `LineId`; a cycle is cut at its lowest id, which advances first, then the line feeding it, backwards around the cycle (so what crosses the cut lands on a line that has not moved yet and moves again that tick). M42 lines have one link, so a component is a single line or a simple cycle; M44's `Fork` generalises the within-component walk.
