# M39ad: the iPhone's driverless round runs without Tyler

Status: done (2026-10-08) · After: 39ac · Tyler-dependent: no (Tyler asked for it 2026-10-08; the iPhone is free for this milestone)

## Goal
ADR 0056 judges iOS frame-pacing items only from driverless runs, because a live WDA session degrades WebKit's frame delivery. Today "driverless" means Tyler opens the join URL on the iPhone and taps Start. On 2026-10-08 a resumed QR round (`m39ad-iphone-qr`, second run) never saw the phone for 30 min although Tyler opened the link as told, and the tool cannot say why. When this is done, `pnpm device:walk --auto --open ios --round <r> --only ...` opens the round on the USB iPhone with no person and **no WDA/Appium/XCUITest process alive while anything is measured**, the walk starts without a tap, and the round exits by itself like a driven one (M39w). A refused or never-arriving phone is visible in `--status`.

## Scope
1. **Telemetry first** (red tests first). `phone-api.mjs` counts and logs every refused phone request with its reason (`host`, `token`, `origin`, `cut`), the Host header and an 8-char token prefix, and every `GET /__walk/runner.html` served. `--status --json` gains `phone.requests: {served, refused: {<reason>: n}}` and the last refusal. The tool's stdout prints one line on the first refusal of each reason.
2. **Tunnel warm-up covers the runner.** `warmTunnel` fetches `/__walk/runner.html` (and the agent script it loads) through each tunnel that serves it, and the join URL is printed only after that path answers 200 with the expected headers. A warm-up that never succeeds within its existing bound fails the start loudly instead of printing a dead URL.
3. **Auto-start.** `runner.html` accepts `&autostart=1`: after the 30 s idle probe passes it sends `walk start` itself (no Start tap, no `autolock` sheet). Keep everything else the probe checks. If the wake lock needs a gesture, don't request it: Auto-Lock Never is a precondition of the iPhone (PROMPT, `iphone-low-power-autolock` memory), so record `wakeLock: "skipped (autostart)"` in `env`.
4. **A non-WDA opener.** Verify on the USB iPhone 12 (UDID `00008101-001845EE1A82001E`, free for this milestone) which of these opens an https URL in Safari with no XCUITest/WDA: `xcrun devicectl device process launch --device <udid> --payload-url <url> com.apple.mobilesafari` (check the real flag names with `xcrun devicectl device process launch --help`), or `pymobiledevice3` (installed via pipx; e.g. its `webinspector`/`developer` commands, and note whether it attaches the Web Inspector: an attached inspector is not driverless, ADR 0056). Use the first that works without an inspector session; paste the command and what the phone showed (a screenshot via `pymobiledevice3 developer dvt screenshot` or `idevicescreenshot`, if available, is evidence). If none works, stop and report with what each printed; do not fall back to WDA (that needs a comparison run first, which is the orchestrator's call).
5. **`--open ios`.** With `--auto --open ios`, the tool opens the join URL with `&autostart=1` through that opener after the tunnel is warm, and re-opens it once if the phone is not seen within 60 s (log both). Before the first measuring window and at every window start, it checks that no Appium, WDA or `xcodebuild` test process is alive (`pgrep` on the existing markers) and fails the round loudly if one is. The round `env` records `opener` and `driver: "none"`. Judge sheets are deferred exactly as in a driven round, and the process exits by itself (`done-pending-judge`). An **act** prompt in this mode has no one to do it: the item ends `skip`, `by: device`, note `NotDrivable: driverless open has no hands (<prompt>)`, never a hang. List, in Deviations, which act prompts M09b-fill-rate, M16-coexist, M29-net-heap and M34-remote-motion show on iOS today.
6. Update `.claude/skills/device-round/SKILL.md` (a short section 1c: the driverless open, its preconditions, and that only it, or Tyler's QR, may be used for iOS pacing items).
