**Departures, and why.**
- *The jam toggles and the inserter edits are game rules, not requests.* The bench lines are not in the 32-slot chain table, so `Op::Sink`/`DeadEnd` cannot name them, and the toggle set and phases are M44b's seeded `saturated_view_world` (Rust): a TS-scripted request stream could only copy that selection. So genesis spawns one `Thing::Jam { line, phase, period }` per toggle and, for `InserterLike`, one `Thing::Inserter` (M40's `2,000 / scale` calls a tick from a stateless SplitMix mix of `(seed, tick, call)`), both on the `"spawner"` list (a new active list would add an encoded list to every golden); a jam calls `set_out(Sink | DeadEnd)` on the tick its output changes, the same structure write a request makes. No `Op` was added.
- *The regime has four values, three marker tiles.* `BenchSpec.regime: BenchRegime { Mixed (default), InserterLike, MixedEmpty, SaturatedView { jam_pct, period, speed } }`: the seven worlds need `InserterLike`, M41's "empty at the start" and `speed = 72` besides the brief's two. No spare `aux` exists (the four marker tiles use all 64 bits), so three more tiles at `x = -5..=-7` (tag and `jam_pct`, `period`, `speed`) are written, all 0 (the plain tile) for `Mixed`: the worldgen output is unchanged, `golden-bench-64.json` (`46f44b15f176be73`) did not move, `pnpm golden belts` is idempotent. The params themselves are postcard-encoded by the host (`worldgen_params_bytes`), which cannot skip a field, so `regime` is always encoded (+1 B; not hashed, no golden moved); a world persisted with a pre-M47b bench spec would not decode its params (none exists: fixture only).
- *When the fixture declares.* A spawner declares on the tick it joins the list, after its first step (a request's tick; tick 1 for a genesis spawner, not genesis itself): the tracker arms a declaration from the next tick, and the fixture steps a new spawner in the tick it joins. `kinds` is 0 for a `Thing::Spawner`, not the brief's 1 (the engine's `Schedule::cycle` with `kinds` 1 gives item 1 whatever the item), `CYCLE_KINDS` (6) for a `Thing::Cycling`. The fixture's arithmetic already was the engine's rule (`acc += 256`, attempt at `acc >= period`, `-= period` / `-= 256`): nothing in it changed. A destroyed line drops its declaration in the engine (`Tracker::destroy`); the fixture never destroys a spawner entity, so it never calls `set_spawner(.., None)`.
- *Three test-only exports, one ABI move (42 to 43).* `sim_line_items` (every host line's items into the sim's 64 KiB `Tx`), `client_line_items(line)` (one held line: the client's `Tx` is 4 KiB, so `lineStructures` and a whole-replica dump do not fit a 1/64 world's 54-78 lines) and `client_forecast_catch_up(tick)`; `engine/test`'s `hostLineItems`, `lineItems`, `client.forecastCatchUp`. These touch `abi/`, `game_instance.rs` and `src/abi.ts`, outside the brief's file list; the brief's "keep `ABI_VERSION` moves to one" asked for exactly this kind of reader. Section 13 got its name in `net-sections.ts` (`counters(i).sections.Forecasts`, how sections 12 and 13 are counted: whole-section wire bytes of every delivered frame).
- *The arbiter steps a frameless tick itself.* On a tick no frame came for (nothing changed for the client) it calls the follower's catch-up to the host's tick, the step `on_frame` takes first when the next frame comes: the native arbiter's rule. The `SaturatedView` (20, 20) world has 73 such ticks of 300.
- *Chunk pacing lifted in every bench scenario* (`beltsBenchWorld`, `tick-belts-large node`'s choice): the fixture's spawners are entities that write a chunk delta per insert (thousands a second at full scale), which alone degrade the connection and collapse chunks into snapshots; a collapse resends the anchored lines' lists. The measured sections are 12 and 13; with default caps the first arbiter world lagged 195 ticks of 300. Hashing is production in the bytes scenarios, hash-all in the arbiter and the jam test.
