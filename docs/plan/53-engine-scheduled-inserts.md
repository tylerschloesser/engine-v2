# M53: Engine: scheduled inserts as transport state

Status: done (2026-10-12) · After: 49 · Tyler-dependent: no (keeps his spawner line exactly: a configured rate, waiting while full, never a burst)

Split from the M53 sketch on 2026-10-12 (the manager's survey `m53-research.md` in the session scratchpad): the reference spawner's rule needs held credit per lane (README "Belts", Spawner: "an integer accumulator per lane, never a burst"), 0079 §19 (e) forbids writing the entity per insert, and the engine's schedule credit (`Schedule.acc`) is derived, host-only, unreadable by the sim and lost on restore. So the schedule becomes transport state and the engine performs the scheduled insert itself; the game writes once, at configuration.

## Goal
A line's spawner schedule (`period`, `acc`, `kinds`, `next`, plus `paused` by the item cap) is sim state in the transport store: encoded, hashed, restored, carried by surgery to the piece that holds the line's back; `advance` performs the schedule's `insert_back` on the host and the replica follower replays the same rule; `set_spawner` writes that state once and the game never calls `insert_back` for a scheduled line; `declare_spawners` becomes unnecessary for scheduled lines (kept for games that insert themselves); the forecast's spawner mismatches vanish by construction; `fx-belts`' `Thing::Spawner`, `Thing::Cycling` and `Thing::Feeder` move onto the engine schedule so the bench proves it.

## Scope
- **State.** The line record gains `sched: Option<Schedule>` (`period`, `acc`, `kinds`, `next`, `paused`) encoded behind a presence bit of the line's tag (as segments ride bit 7, 0079 §13), so a line without a schedule is byte-identical to today and no golden of a schedule-free world moves; hashed with the store (the full hash); **not** in the per-chunk structure hash (0079 §17 (b): motion state, replicated by the forecast's `RunList` as today); restored with the store (no `declare_spawners` needed: the hook stays, default nothing, for games that insert themselves; `Host::after_from_parts` arms the tracker from the restored schedules).
- **The engine inserts.** At the start of `advance` (before any line moves, so the insert lands before the tick's advance as a game's `insert_back` did), every scheduled line runs the schedule's rule exactly as `forecast.rs:62-84` states it: `acc += 256`; if `acc >= period`, one `insert_back(next)` (at most one a tick); success `acc -= period` and `next` steps (`kinds` as today); refusal for room `acc -= 256` (credit kept, never grows: no burst); refusal by the item cap sets `paused` (a `State`), the next success clears it. `set_spawner` enforces `period >= 256` (`BadPeriod`). The tracker's `step_spawner` keeps its checks but can no longer mismatch on a scheduled line (the same rule produced the insert); `spawner_mismatches` stays as a counter and reads 0.
- **`set_spawner(line, Option<Schedule>)`** writes the state and resends the line's list (as today, so the follower gets the new schedule); `Err(BadPeriod)` below 256, `Err(BadItem)` for `next == 0`. A game's `insert_back` on a scheduled line is refused (`Err(Scheduled)`; a debug assertion names it).
- **Surgery carries the schedule to the back.** `join(front, back)`: the back line's schedule moves to `front` (whose back is now the back line's back); if `front` also has one, `join` is refused (`Unsupported`). `split(line, at)`: the schedule moves to the new back piece. `destroy`: dropped. `extend_back`/`shrink_back`/`rescale`: kept.
- **Replica.** The follower's replay rule is unchanged; the `RunList` still carries the schedule (A3 rule 4); `apply_structure` ignores schedules; a replica's store never runs the insert (only the host's `advance` does).
- **Fixture.** `Thing::Spawner`/`Thing::Cycling` set the schedule once when they join and then neither insert nor write (their stored fields may stay for shape; the entity's tick becomes a no-op); `Thing::Feeder` likewise (period 256). The fixture's `declare_spawners` becomes a no-op. The bench world's spawners therefore write nothing per insert: `belts_feeders_write_no_delta` extended to every regime; `spawner_mismatches` 0 and undeclared inserts 0 everywhere. `pnpm golden belts` exactly once, the diff stated per scenario (the entity shapes and the store's bytes change where schedules exist).
- **Tests.** Engine (`tests/main/forecasts.rs` or a new `tests/main/schedule.rs`, plus `transport` unit tests): `schedule_is_state` (encode/decode round trip; the hash moves with a schedule change; a line without one byte-identical), `schedule_inserts_at_the_predicted_ticks` (the arbiter: host items equal the follower's over 600 ticks on the seven 1/64 worlds, 0 mismatches), `schedule_credit_never_bursts` (a stalled spawner inserts once when room returns), `schedule_paused_by_cap` (the item cap pauses and resumes with `State`s), `schedule_follows_surgery` (join to the merged line; split to the back piece; destroy drops; both scheduled refuses), `schedule_survives_restore` (save/restore through the host with `declare_spawners` a no-op; inserts continue exactly; §20 (a)'s test re-pointed), `insert_back_on_a_scheduled_line_is_refused`; `no_alloc_*` unchanged and green; the wasm determinism golden for the fixture re-blessed by `pnpm golden belts`. ## Planning decisions
- **The schedule is state and the engine inserts** (0079 §21): the only placement of the held credit that is deterministic, restored and written once; the forecast replay and the authoritative insert are the same rule, so mismatches cannot occur. 0076 §3's "`insert_back` is the game's" stands for unscheduled lines; a scheduled line's inserts are the engine's.
- **No `LineStructs` change**: the schedule keeps riding the `RunList` (A3 rule 4), so the wire and its pins hold; the full hash covers it as the store's state.
- **Surgery follows the back**, because a spawner inserts at its line's back; two schedules meeting at a `join` is the game's error, refused.
- **The bench re-baselines only if the measured delta is real**: the fixture's spawners stop writing deltas (frames cheaper) and `advance` gains the schedule step (tick dearer); the manager attributes and records.
