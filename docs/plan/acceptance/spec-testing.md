## Notes on the rows

- **R2:** `rg 'vi\.(mock|spyOn)'` finds three files: `packages/engine/src/client.test.ts` (two `WebAssembly.compileStreaming` spies), `packages/engine/src/server.test.ts`, `packages/engine/src/vite.test.ts` (a `node:fs` mock). Each looks justified, but no test caps the mocking or lists the allowed sites, so nothing fails if mocks spread. ADR 0020 "Alternatives rejected" records the intent.
- **R4:** `zeroGcSuite` (`packages/engine/tests/browser/gc/suite.ts`) generates `<page> clean` and `<page> neg <object|burst> <isolate>` titles. Only `gc-loop`'s `burst` controls stay in the fast tier; every other page's `burst` title carries ` @slow` (for example `reference neg burst main @slow`). The clean test asserts `r.verdict` equals `{ pass: true, ... }` and that every expected isolate thread is present in the trace, so a lost trace cannot read as "no GC". `analyse.ts` asserts `MinorGC + MajorGC === 0` on strict isolates and `MajorGC === 0` on budgeted ones.
- **R5:** the per-suite budgets (rust 10 s, unit 3 s, wasm 7 s, netcode 10 s, browser 48 s) run concurrently, and `classifyBudget` only fails at 1.5x the budget (browser: 72 s). A run of 65 s therefore prints WARN and exits 0, and no total wall-clock check against 60 s exists. A small test or runner change: fail `pnpm test` (fast tier, scale 1) when the whole run's wall time passes 60 s, or assert in a unit test that every fast `budgetMs` x `FAIL_MULTIPLE` is at most 60 000.
- **R6:** `scripts/measure-rebuild.mjs` flags a median over 45 000 ms, but it is a manual script, not a test, and nothing runs it in `pnpm test` or CI. ADR 0049 accepts that as a flag, not a gate. No device check exists for it.
- **R7:** one line per suite (`formatSuiteLine`), failure text capped (`formatFailure`), `unit` budget 3 s and `CLAUDE.md` cap 60 lines (`context-artifacts`), and the runner's own failure path (`runner_negative_control`, driven by `pnpm test --self-check-fail`).
- **R8:** `.github/workflows/ci.yml` (ubuntu-latest, `ENGINE_GPU=swiftshader`, `pnpm test` and `pnpm test:slow`) has no test asserting it stays that way; a small test could parse the YAML and assert `runs-on: ubuntu-latest`, `ENGINE_GPU: swiftshader` and both `pnpm test` steps. The verdict tests cover the software-adapter ceilings only. Per `docs/plan/device-checks.md`, no device check is ticked yet, so the `device:` entries will fail `acceptance:check` until Tyler runs them.
- **R9:** the net worker is budgeted in `budgets.json` as `bytesPerFrame: 244` (class `budgeted`, `multiplayer-topology` page, calibrated against real presence traffic), not as a literal 1 KB per message. Allocations beyond that calibration, or any `MajorGC`, fail the clean test, and `gc/net-negative-control` proves a per-message parse trips `net` alone while `main`, `client` and `gen0` still pass. Render-thread floor: `main` rows hold 110-234 B/frame (for example `terrain`: 110). No test pins the literal 1 KB per message figure.
