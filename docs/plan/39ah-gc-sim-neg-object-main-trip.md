# M39ah: `[gc] sim neg object sim` trips `main` on CI

Status: not started · After: 39ag · Tyler-dependent: no

## Goal
The negative control `[gc] sim neg object sim` (`packages/engine/tests/browser/gc-sim.spec.ts`, generated by `gc/suite.ts`) has failed on CI three times in software mode (SwiftShader): CI runs 37507742158 (push `9988a02`, ledger row 170), 37884536875 (`37799e1a`) and 37953467887 (`77012637`, 2026-10-09). The last two have the same shape. The `sim` control trips `sim` as it should, but `main` also trips: `verdict.B.main` is `false` where `expectedVerdict` wants `true`. In both artefacts `attributedBytesPerFrame.main` is **0.0933** (56 B over 600 frames: one object under the `drive` attribution root), against the software-mode budget `gc.pages.sim.software.isolates.main.attributedBytesPerFrame: 0` (`packages/engine/budgets.json`). The rest is almost identical between the two runs: `bytesPerFrame.main` 25.97 / 26.05 and the `byFn.main` table. Row 170's rule (second occurrence → pull the artefact and compare per isolate before any remedy) has been followed: the artefacts are attached to those runs (`gh run download <id>`, `test-results/packages/engine/test-results/gc-sim-sim-neg-object-sim-gc/error-context.md`). When this is done, the source of that one main-isolate allocation is named and removed, or shown to be harness-side and excluded by a correct rule. The control trips only `sim`.

## Deviations
- Cause: harness-side. `instrument.ts` chose the lower window by raw total, then read attributed bytes from that winner. Temporary dump (reverted) showed main's attributed bytes were `128` (or `56`) in window 1 and `0` in window 2, always under `run > drive(gc-page) > drive(gc-sim) > stepSimTickSync > load@:0` (the `Atomics.load` builtin), raw totals e.g. `[13860, 14812]`, so window 1 won on raw total. `sim clean` never shows it (only the control run).
- Local repro: `ENGINE_GPU=swiftshader GC_MODE=software pnpm test browser -t "sim neg object sim"`: red 5 of 6 attempts (the 56 B variant in 1 of them). Note CI's env also needs `GC_MODE=software` (ENGINE_GPU alone leaves hardware arithmetic).
- Fix: `gc/instrument.ts` now records `attributedWindows[name]` per window and uses `Math.min` as `attributedBytesTotal`; `byFn` still comes from `lowerWindow`. Source-string test added in `analyse.test.ts`. No budget, control or retry change.
- Evidence after: `sim neg object sim` 6/6 green; `-t 'gc-sim.spec'` (clean, neg object main, neg object sim, 2 more) green 10 times in a row. `sim neg object main` (a deliberate per-frame allocation under `drive`) still trips main in both windows, so the minimum keeps it.
- Not run: full `pnpm test`/`pnpm lint` (orchestrator).
