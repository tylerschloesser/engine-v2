# 0020: Testing strategy

Status: Accepted (2026-09-19). Amended by [0024](0024-planning-amendments.md) §14, [0031](0031-browser-suite-five-workers.md) (§3's `workers: 3` line), and [0033](0033-fast-tier-budget-after-build-fix.md) (§3's budgets).

## Context

Requirements in [`../spec/testing.md`](../spec/testing.md): automated coverage an LLM agent can drive, little mocking, low-level browser behaviour testable, everything under 1 minute on warm caches, a ≤ 30 s incremental rebuild, Linux CI on a software WebGPU adapter, iOS by manual checklist. The main reader of test output is Claude, so context cost counts as much as wall clock. Other ADRs own what is asserted (determinism rules [0002](0002-determinism-same-wasm-everywhere.md), zero GC [0016](0016-zero-gc-definition.md)); this one owns tools, structure, budgets and harnesses.

## Decision

**1. Tools** (pinned versions: [0017](0017-packaging-and-build.md) section 10). Rust: **cargo-nextest** (timeouts, slow-test report, `default-filter` profiles for fast/slow; `cargo test` keeps working). TypeScript and anything hosted in Node: **Vitest in Node mode** (dev dependency; shares the reference game's Vite config). Browser: **`@playwright/test`**, test bodies in Node, `channel: 'chromium'`, raw CDP through `newCDPSession`/`newBrowserCDPSession`. Exploratory looks at the running game: the **Playwright CLI skill** (`playwright-cli`; snapshots and screenshots go to disk, not into context). Chrome DevTools MCP is added only for a specific perf or leak investigation. All are dev-only; the published package keeps zero runtime dependencies ([0017](0017-packaging-and-build.md)).

**2. One entrypoint, quiet by default.** `pnpm test [suite] [-t <pattern>]` runs the incremental build, then all fast suites in parallel. Output contract: one line per suite (`name pass|FAIL tests duration/budget`), then for each failure only: test name, assertion message, seed, and paths to artefacts (trace JSON, actual/expected/diff PNG, action log, top allocation sites) under a gitignored `test-results/`. Nothing else on stdout; non-zero exit on failure. A suite over budget prints a warning; over 1.5x budget fails. `pnpm test:slow` runs the slow tier the same way. Every test is addressable by name so an agent can run one in a second or two. `pnpm lint` (format, lint and type checks; commands and tool pins: [0017](0017-packaging-and-build.md) section 10) is a separate command with the same quiet-on-success contract, outside the suite budgets because clippy and `tsc` compile; both commands are verifying commands of every milestone, and the no-compile subset gates commits ([0021](0021-context-architecture.md)).

**3. Suites and budgets** (Tyler's Mac, warm caches; 55 s if run serially, about the browser suite's 25–30 s in parallel):

| Suite | Runner | Contents | Budget |
|---|---|---|---|
| Rust native | nextest | unit tests; scenario tests ending in a golden state hash; log replay; `admit` and other host-only paths ([0001](0001-camera-and-presence.md)); cache-invisibility replay at capacity 1/default/unlimited with shuffled generation order ([0007](0007-world-model.md)); CPU-side DrawList hashes; WGSL validation | 10 s |
| TS unit | Vitest | pure TS: camera maths, rings, exports map, config | 3 s |
| WASM under Node and Bun | Vitest + one plain `bun` script | the built game+engine `.wasm` through the server entrypoint: same logs, same golden hashes; ABI and import-allowlist tests ([0014](0014-js-wasm-boundary.md)) | 7 s |
| Netcode | Vitest | section 7 | 10 s |
| Browser | Playwright Test, Chromium new headless, real GPU | zero-GC tests + negative controls ([0016](0016-zero-gc-definition.md)); readback scenes; canvas smoke; worker/SAB/cross-origin-isolation wiring; sim hash in Chromium, WebKit, Firefox; packaging smoke of the Vite-built reference game ([0017](0017-packaging-and-build.md)) | 25 s |

Compilation is budgeted separately: **≤ 30 s from a one-line Rust edit to tests starting** (native test binaries + the `wasm32` module). Cold builds (fresh clone, new worktree, CI without cache) are outside both budgets. Browser tests never use real `requestAnimationFrame` pacing (600 frames would cost 10 s); they step frames manually (the spike's 600-frame window took ~20 ms).

**4. Demotion rule.** A test stays in the fast tier only if its p95 is ≤ 0.5 s (Rust/Node) or ≤ 3 s (browser). When a suite exceeds its budget, demote in this order: multi-engine repeats of a test that already runs on one engine; real-socket repeats of in-memory netcode tests; large-world, soak and long-replay variants; heavy mode; anything measuring wall clock. Never demote the only test covering a feature; shrink its scenario. Mechanism: a `slow` tag (nextest `default-filter`, `@slow` grep in Vitest and Playwright).

**5. Determinism assertions.** Recorded action logs for fixture games and the reference game are replayed with state hashes compared at several checkpoints (so the first divergent tick is reported) in: native nextest, the `.wasm` under Node and under Bun, and a bare page with the `.wasm` in a worker in Chromium, Playwright WebKit and Playwright Firefox. The sim hash needs no GPU, so headless Firefox and Linux WebKit (WPE/GTK, still JavaScriptCore) qualify. Golden hashes are checked in and regenerated only by an explicit command from the `.wasm` run, which [0002](0002-determinism-same-wasm-everywhere.md) makes authoritative. The worldgen golden test hashes raw tile bytes and float bits ([0008](0008-chunk-generation.md)). Slow tier: heavy mode (save, reload into a fresh instance, continue, compare; defined in [0002](0002-determinism-same-wasm-everywhere.md)) at N = 1. Dev builds check every chunk hash every frame ([0013](0013-sessions-and-integrity.md)).

**6. Headless WebGPU and rendering.** Locally `channel: 'chromium'` gives a real Metal adapter headless (`vendor: apple, architecture: metal-3`); `--enable-unsafe-webgpu` is passed anyway so one config serves Linux. Linux CI uses SwiftShader: `--enable-unsafe-webgpu --enable-features=Vulkan --use-angle=vulkan --use-vulkan=swiftshader --use-webgpu-adapter=swiftshader --disable-vulkan-surface` with `libvulkan1` and `mesa-vulkan-drivers`. Every GPU test asserts and records `adapter.info` and fails, never skips, on a null adapter. Playwright WebKit has a working headless adapter on macOS: one readback scene in the slow tier. Playwright Firefox returns a null adapter headless: sim hash only. Rendering is verified in three layers, cheapest first: (a) the DrawList and buffer bytes `extract` produces are a pure function of replica + camera and are hashed exactly, no GPU ([0018](0018-renderer.md)); (b) a handful of scenes render to a fixed-size offscreen `rgba8unorm` target, `copyTextureToBuffer` + `mapAsync`, compared in Node: **semantic pixel probes** are the gate ("centre of tile (3,4) is tile type X's colour", "nothing outside the viewport"), goldens are secondary at ≤ 2/255 per channel and ≤ 0.1 % differing pixels, regenerated only by an explicit command; scenes use nearest sampling, integer-aligned quads, no MSAA; (c) one canvas-presentation smoke test. **Page screenshots are never used for pixel assertions** (compositor, colour management, DPR; headless Linux captures WebGPU canvases as black). Every browser test also fails on `uncapturederror`, device loss, or a non-empty `getCompilationInfo()`. If Metal and SwiftShader disagree beyond tolerance, add a per-adapter-class golden rather than widening tolerance.

**7. Netcode harness.** One Node process holds the real server entrypoint with the real `.wasm` and K real headless clients (the client sync layer without DOM or renderer), each with its own instance, joined by the production `Connection` interface ([0009](0009-transport-and-hosting.md)). Two implementations are exercised: an in-memory `Connection` pair (most scenarios; it is an adapter like any other, the code on both ends is real) and real `ws` sockets on `127.0.0.1:0` (a subset). A **conditioner** wraps any `Connection`: per link, one seeded PRNG draws `deliverAt = now + latency + jitter`; loss is modelled as what TCP turns it into, a head-of-line stall for a drawn RTO with order preserved, or a scripted disconnect; message drops apply only to `latest-wins` traffic on a datagram adapter. Time is a virtual clock: `advanceTo(t)` awaits physical arrival of every message with `deliverAt ≤ t`, then releases them in the total order `(deliverAt, link, seq)`, so a run is reproducible from `(seed, scenario)` even over real sockets. Failures print the seed and dump the action log. Assertions: after quiescence each client's replica hash equals the host's hash of that client's subscribed region; bounded mispredictions; bytes per client per tick; reconnect, late join, version-mismatch rejection. One Playwright test with two pages against a real server is the end-to-end smoke.

**8. What the engine must expose** (behind a `test` entrypoint that is absent from production bundles): one injectable `Clock`/`Scheduler` on main thread, workers and server, with no `Date.now`, `performance.now`, `setTimeout` or rAF outside it; `stepTick()` on the host and `stepFrame(dt)` on the client plus an awaitable cross-thread quiescence point (sequence/ack counters on the SAB rings, [0015](0015-threads-memory-and-topology.md)); a caller-supplied render target; whole-world and per-region state hashes at any tick ([0002](0002-determinism-same-wasm-everywhere.md), [0013](0013-sessions-and-integrity.md)); every seed a parameter; input injected as engine-level events ([0019](0019-camera-input-and-overlay.md)), with one or two tests on the real DOM path; deterministic counters; the negative-control allocation hook. Engine tests use tiny fixture games, one per feature; the reference game adds the scripted coverage listed in [0003](0003-game-facing-api.md).

**9. Performance.** Fast tier: deterministic counters only, asserted as exact values with ceilings held in one checked-in **budgets file, `packages/engine/budgets.json`** (outside the package's `files`, so never published; every ADR that says "budgets file" means this path): bytes and messages per client per tick and per chunk subscribe, JS bytes per frame per isolate ([0016](0016-zero-gc-definition.md)), draw calls, upload bytes and pipeline switches per frame, WASM memory high-water mark. Raising a number in it is a reviewed change. Slow tier: wall clock (native tick-time benchmarks on the standard large save below; browser frame time from a CDP trace with real rAF), against a checked-in baseline with a 25 % threshold, gating only on Tyler's Mac.

**The standard large save** is the reference game with the default state budget of [0007](0007-world-model.md) full, because that is the largest world the baseline phone must tick:
- Entities: the 32 MiB entity share / 128 B nominal = **262,144 furnaces** (`max_entities`), the reference game's only entity. At the dense-chunk figure of [0010](0010-rates-and-subscriptions.md), 200 furnaces per chunk (800 of 1,024 tiles under 2x2 footprints), that is 262,144 / 200 = **1,311 chunks with entities** (chunk indexes: 1,311 x (128 B + 800 x 6 B) ≈ 6.4 MiB, inside the 8 MiB share).
- Modified tiles: the 12 MiB overlay share / 12 B = **1,048,576 depleted resource tiles** (`max_modified_tiles`), at 256 per chunk = **4,096 modified chunks**.
- Load: every furnace fuelled and smelting with uniformly staggered start ticks, so 262,144 / 100 ticks per ingot ≈ **2,621 timer completions per tick**, each one whole-value put; **8 connected headless players**, each subscribed to 121 dense chunks (the maximum view) and sending one action per second (the "active" rate of [0004](0004-action-timing-and-rejection.md)). This is a CPU worst case and deliberately beyond the bandwidth budget; frames are built and discarded.
- It is not a stored file: a seeded, checked-in builder produces it through a bench-only `genesis`, so it follows format changes. The benchmark reports the median and p99 of 1,200 ticks after 200 warm-up ticks; the numbers it must meet are owned by [0010](0010-rates-and-subscriptions.md).

**10. CI and devices.** GitHub Actions, `ubuntu-latest`, fast and slow tiers on every push, SwiftShader adapter, `Swatinem/rust-cache` and a cached Playwright browser directory; timings are recorded, never gating. Real-GPU rendering and timing runs happen only on Tyler's Mac. iOS Safari: a checked-in manual checklist run on Tyler's phone before a milestone is called done: page is cross-origin isolated and gets an adapter; the determinism page shows the golden hashes; pan, pinch and tap; ten minutes of play with no reload or visible hitch; background and foreground; network switch and reconnect. **Environment note:** on Tyler's Mac native `cargo` linking fails until the Xcode license is accepted; the runner exports `DEVELOPER_DIR=/Library/Developer/CommandLineTools` on macOS when it is unset.

## Alternatives rejected

- **Playwright MCP:** tool schemas and accessibility snapshots enter the context on every step; Microsoft's own README points coding agents to the CLI.
- **Vitest browser mode:** the runner, its RPC and assertion library share the V8 isolate under test, polluting the allocation and GC measurements; launch flags and browser-level tracing are a layer further away. It suits DOM component tests, which the engine does not have.
- **`node:test`:** no dependencies, but weaker filtering, reporting and project-level parallelism. **wasm-bindgen-test:** no wasm-bindgen ([0014](0014-js-wasm-boundary.md)); the shipped `.wasm` is tested through the server entrypoint instead.
- **Mocked sockets, Toxiproxy, `tc`/`dnctl`:** mocks hide framing and backpressure bugs; the others are real-time, unseedable, external and privileged.
- **Exact hashes of GPU output, perceptual diff libraries, Dawn node bindings as the main path:** break across adapters; unneeded for flat tile scenes; not the shipped stack.
- **GPU or macOS CI runners:** 3–4x and 10x the cost of Linux minutes; Requirements fix Linux with a software adapter.
- **Counting compile time inside the 60 s:** a cold dependency build alone exceeds it.

## Consequences

- Testability shapes the engine API (section 8) from the first line of Phase 3 code.
- Deferred to Phase 3: **spike B** (SwiftShader WebGPU in Chromium on a stock `ubuntu-latest` runner: packages, old vs new headless, agreement with Metal within tolerance, install time). It does not block: CI-on-SwiftShader is a Requirement, the local loop is proven, and the fallback is known (Dawn node bindings for readback in CI, or GPU tests local-only). It runs with the first CI workflow.
- Deferred to Phase 3: **spike C** (byte-identical traces across 100 runs of one seed over loopback `ws`; target a 60 s, 4-client session in under 2 s). It does not block: the in-memory path is deterministic by construction, and if real sockets prove unreproducible they drop to a smoke test without changing the design.
- Deferred to Phase 3: measuring the 30 s rebuild target and the per-suite numbers, and choosing sccache vs a shared `CARGO_TARGET_DIR` for agent worktrees, because no code exists to measure.
