# 0044: Bun is pinned at 1.4.2, and is a server host as well as a test leg

Status: Accepted (2026-09-30). Amends the Bun row of [0017](0017-packaging-and-build.md) §10 (version 1.3.8, scope "Bun leg of the WASM suite only"); implemented by M35b (step 6).

## Context

[0017](0017-packaging-and-build.md) §10 pinned Bun 1.3.8 for the Bun leg of the `wasm` suite only, on the evidence of the `vite-lib-worker-wasm` spike (same state hash as Node). [0009](0009-transport-and-hosting.md) names Bun a primary server target, and M35b adds `engine/server/bun` and `games/reference-server`'s `start:bun`, so a Bun process now has to stay up for hours, not for the one second a test leg takes.

It does not under 1.3.8 on macOS (Darwin 27, Apple silicon): the process is killed with SIGTRAP (exit 133) about 10 s after any `WebAssembly.compile`, even idle, even for an empty module. A script with no compile, or one that only constructs a `WebAssembly.Memory`, lives. `BUN_JSC_useJIT=0`, `useBBQJIT=0`, `useOMGJIT=0`, `useWasmIPInt=0`, `useConcurrentJIT=0` and `useWasmFastMemory=0` do not help. Node 22 runs the same game for 30 s without incident. Bun 1.3.8 also never settled `await Bun.serve().stop()` after the server had closed a socket itself in the same process.

## Decision

**1. Bun 1.4.2** replaces 1.3.8 in `scripts/setup-tools.mjs` and `.github/workflows/ci.yml`; those two sites and 0017 §10's row are the one pin.

**2. The scope widens** to "the Bun leg of the `wasm` suite and the `engine/server/bun` host".

## Alternatives rejected

- **Keep 1.3.8 and drop Bun as a long-running host.** Bun is a primary target in 0009; the fast-tier test would pass while `start:bun` served for 10 s.
- **Work around it in the adapter.** The crash happens with no engine or adapter code involved.

## Consequences

- Verified under 1.4.2: the empty module and `games/reference`'s release `game.wasm` run past 20 s with exit 0; `start:bun` served the reference game for more than 80 s with a browser Collect round trip; `await Bun.serve().stop(true)` settles after a server-side close (the M35b loopback test awaits it).
- The `vite-lib-worker-wasm` spike's hash match was measured on 1.3.8; the `wasm` suite's Bun leg (golden hashes) is the standing proof under 1.4.2.
- Not checked on Linux. Revisit when CI's first run under 1.4.2 differs, or when a later Bun release is wanted.

## Sources

- Reproduction (2026-09-30): `await WebAssembly.compile(bytes); setInterval(() => {}, 2000)` under `bun` 1.3.8 exits 133 at about 10 s; 1.4.2 (npm `bun@1.4.2`) exits 0 past 20 s.
- M35b Deviations, `docs/plan/35b-bun-and-deno-adapters.md`.
