# Simulation: the tick loop, actions, time and randomness

The sim is a deterministic, tick-stepped state machine. One `Game` implementation (Rust, in the game crate) supplies the rules; the engine supplies the loop, the world store, ordering, validation, the clock and the RNG. The same `.wasm` runs the sim on a server (a JS runtime) or in a worker (single-player), and the same `apply` also runs on every client for prediction ([0002](../decisions/0002-determinism-same-wasm-everywhere.md)). Rust: `packages/engine/crates/engine/src/` (`game.rs`, `sim/`, `authority.rs`, `budget.rs`, `time.rs`, `rng.rs`, `host/`, `game_instance.rs`, `clock/`). TypeScript: `packages/engine/src/server.ts` (pacing), `host/lifecycle.ts` (idle), `clock.ts` (injected clock), `clock-block.ts`, `sim-config.ts`. Reference game rules: `games/reference/sim/src/lib.rs` (`apply`, `tick`), `content.rs` (durations). Wire, sessions and prediction: [sync-and-netcode.md](sync-and-netcode.md). World model and store: [world-and-worldgen.md](world-and-worldgen.md). Log, snapshots, recovery: [persistence.md](persistence.md).

## The `Game` trait

`engine::game::Game` ([0003](../decisions/0003-game-facing-api.md), amended by [0023](../decisions/0023-action-growth-declaration.md), [0024](../decisions/0024-planning-amendments.md) §7, [0046](../decisions/0046-genesis-writes-unlogged-and-timers.md)) is implemented once per game and the generated exports (`export_game!`) build one `GameInstance<G>` (`game_instance.rs`) that dispatches by role: `Sim` is `host::Host<G>`, `Gen` is the worldgen core, `Client` is `ClientInstance<G>`.

- Consts: `SCHEMA_VERSION`, `TICK_RATE` (default `TickRate::HZ_20`), `CHUNK_BITS`, `GAME_VERSION`.
- Sim hooks: `register`, `prototype`, `anchor` (min-corner tile of the footprint), `genesis`, `on_player`, `apply`, `predict` (opt-out flag only), `growth` (provided; see state budget), `tick` (host only), `admit` (host only, never replayed), `migrate` ([persistence.md](persistence.md)).
- Rules read and write the world only through `WorldRead` / `WorldWrite` (`world_access.rs`, object-safe, used as `&mut dyn WorldWrite<G>`). Implementors: `Authority<G>` (host: reads never `Unknown` except a missing player; every write is one whole-value put that records one `Delta` and derives its scope from footprint or player), `Predicting` (client overlay) and the read-only view. Games write no deltas, no save/load, no second prediction rule.
- `Game::tick` receives `TickCx` (`authority.rs`): an `Authority` plus `next_woken`, `next_due`, `wake`, `wake_at`, `cancel_wake`, `activate`/`deactivate`/`active_len`/`active_at` and player iteration. Timers, the wake queue and per-system active lists live in `sim/timers.rs`, `sim/wake.rs`, `sim/active.rs` and are sim state (snapshotted and hashed). At most one timer per entity; `wake_at` is callable from `genesis` and `tick` only. Every `spawn`/`put_entity` made outside `tick` (in `apply`, `on_player`, `genesis`) queues the entity for `next_woken` in that tick's `tick` call; puts through `TickCx` and `migrate` (`spawn_no_wake`/`put_entity_no_wake`, which restores the queue itself) never auto-wake.
- Genesis writes are not logged and may arm timers ([0046](../decisions/0046-genesis-writes-unlogged-and-timers.md)).
- Authors' rule inside `apply`: validate first, write after; copy-modify-put; `?` on every read ([prediction rule](../../.claude/rules/prediction.md)). Add a new action with the [add-action-type skill](../../.claude/skills/add-action-type/SKILL.md).

## The tick

`Sim<G>::step` (`sim/mod.rs`; `step_with_progress` adds a hook the host uses to write a crash-locating `Progress` cursor before each game-authored call) runs one tick over the records queued for it, in this order:

1. For each `Record` in arrival order: `Record::Player` calls `G::on_player` (and then sets the engine roster bit for `Connected`/`Disconnected`); `Record::Action` runs the state-budget check, then `G::apply`, then records `last_seq = seq` for that player (`Authority::record_ack`) and pushes an `Outcome { seq, result }`.
2. `Authority::begin_tick` (swap the wake queue's `next` into `now`; compact active-list tombstones), `G::tick(TickCx)`, `end_tick` (drop what `now` still holds), `advance_tick` (tick counter + 1).

Crash location: `persist/progress.rs` `Phase`/`Progress` is a cursor the host writes before each game-authored call so a trap names the record that caused it. `bench_phase.rs` `mark` is per-phase tick timing, compiled out unless the `bench-phases` feature is on, and never feeds state.

`Host::tick` (`host/mod.rs`) wraps `step`: it takes `pending_records`, steps, stamps chunk versions from the change log, routes each `Outcome` to the sending connection's `pending_results`, then refreshes subscriptions. `Host::seal` clears the change log after every connection's `build_frame`. Ticks are never run by clients: a client holds a partial replica and only re-runs `apply` for pending actions.

Pacing is TypeScript (`server.ts`, `createSimHost`): a timer fires every `Math.round(1000 / tickHz)` ms and runs one tick. Every `RESYNC_TICKS` (8) ticks it reads the injected `Clock` once, and if real time is behind it runs up to `MAX_CATCHUP_TICKS` (5) extra ticks and drops the rest (`counters.ticksDropped`, `tickOverruns`). The clock is read this rarely so the tick path allocates nothing ([hot-paths rule](../../.claude/rules/hot-paths.md)). Rust never reads time; pacing, bandwidth buckets and rate limits are functions of the tick count (`host/pacing.rs`). Only `clock.ts` (plus `src/test/**`, `src/vite.ts`, `src/build-game.ts`) may name `Date`, `performance`, `setTimeout`, `setInterval` or `requestAnimationFrame` (Biome `noRestrictedGlobals`, `biome.json`); everything else takes an injected `{ clock, scheduler }` so tests drive a manual clock ([0020](../decisions/0020-testing-strategy.md) §8).

Idle worlds: `host/lifecycle.ts` (`createLifecycleTracker`) logs `Disconnected` 10 s after an ungraceful close (`GRACE_MS`; an explicit leave logs at once), stops the timer after the tick that applies the last `Disconnected` unless `WorldConfig.keepTickingWhenEmpty` is set, and after `IDLE_MS` (30 s) snapshots and calls `onIdle` ([0013](../decisions/0013-sessions-and-integrity.md)). A single-player world pauses when the tab is hidden (`client.ts` `attachHostLifecycle`, `SimHost.pause()`). There is no offline progress: the tick counter only advances while ticks run.

## Actions

Decision and table: [0004](../decisions/0004-action-timing-and-rejection.md), amended by [0023](../decisions/0023-action-growth-declaration.md), [0024](../decisions/0024-planning-amendments.md) §8 and [0064](../decisions/0064-phase-3-decisions-sync-and-netcode.md) §10. Actions are the only way to change the sim from outside; the engine-defined ones are connection events (`PlayerEvent::{Joined, Connected, Disconnected}`), the rest are `G::Action`.

- **Timing.** The host assigns every action to the next tick (received during tick T, applied at the start of T+1), in host arrival order, before the tick rules. Clients never choose ticks. The host stamps `who: PlayerId` from the connection. The log's positional order is the canonical order.
- **`seq`.** A per-player `u32` assigned by the client, continuing across reconnects. The host keeps the last processed `seq` per player as sim state (`Store::last_seq`), so a resend (`seq <= highest admitted`) is dropped in `Host::on_uplink` and never applied twice.
- **Admission (host only, unlogged, never replayed)** in `Host::on_uplink`: decode with `decode_canonical` (malformed is a protocol error and closes the connection, not a rejection); the per-connection rate limit (default 20/s, burst 40, `WorldConfig.actionRate`; `Pacing::take_action`) gives `EngineReject::RateLimited`; then `G::admit`. An admission reject is not logged, does not advance `last_seq`, and leaves the action pending on the client.
- **Apply (deterministic, logged).** `Sim::step` first runs the **state-budget check** (`budget::check`), then `G::apply`. A rejection here (`Rejected::Game(G::Reject)` or `Rejected::Engine(EngineReject::StateBudgetFull)`) stays in the log and replays identically, so `apply` and `budget::check` may read only sim state and world params. The result is an `Outcome { seq, result: Result<Applied, Rejected<G>> }`; `Applied` carries nothing (spawned ids are deterministic from the log, [0022](../decisions/0022-entity-ids-and-provisional-ids.md)).
- **A rejecting `apply` must have written nothing.** Debug and test builds panic if it did; release builds roll back through the undo journal (`authority.rs` `UndoJournal`, `UNDO_JOURNAL_ADOPTED`) and count `apply_rollbacks`.
- **State budget.** Puts are infallible, so the budget of 0007 §8 is enforced per action before `apply` (`budget.rs`): an action with `G::growth(a) == Some(g)` is refused iff `g` exceeds the free entities, free modified tiles or remaining ids (`Growth::NONE` always passes, so a full world can still shrink); an undeclared one needs the world's `max_action_growth` headroom in both counts. It never covers `on_player`, `genesis`, `migrate` or tick rules (the headroom margin absorbs them). `budget::audit` panics in debug (counts `growth_violations` in release) when an accepted action added more than it declared. Nominal costs are constants (128 B per entity, 12 B per modified tile).
- **Results.** Outcomes reach the sender in the frame for the following tick, in `seq` order, with the deltas they caused, and are applied atomically on the client (frame format: [sync-and-netcode.md](sync-and-netcode.md)). `Lost` and `NotPredictable` are client-side results, never on the wire.
- **Connection events** go through the same record stream and `on_player`. The roster bit in `Global` scope (`Delta::Roster`) changes only through logged `Connected`/`Disconnected` records. Camera and viewport updates are not actions, never mutate the world, are neither logged nor replayed, and only feed subscriptions ([0001](../decisions/0001-camera-and-presence.md)); presence is likewise outside the core.
- **Log growth.** The log holds every action record (about 12 to 18 bytes each), so "indefinitely" needs no compaction ([0004](../decisions/0004-action-timing-and-rejection.md) table; storage in [persistence.md](persistence.md)).
- Races go to the lower-latency player (arrival order). Accepted for co-op.

## Time units

[0006](../decisions/0006-time-units.md). `time.rs`: `Tick(u32)` is a point on the world's counter, `Ticks(u32)` a duration; sim state stores only these, never seconds and never float time. `TickRate::hz(n)` is the only constructor and is a compile error outside 10..=60. Authors write integers: `TickRate::millis(ms)` / `secs(s)` are `const fn`, integer-only, round to nearest with ties up, and never return zero for a non-zero duration (`const COLLECT: Ticks = TICK_RATE.secs(2)`; `games/reference/sim/src/content.rs`). Conversion happens before the first tick, never inside one; `apply` and `tick` see only `Ticks` and schedule with `done_at = w.tick() + d`. Per-second rates use an integer accumulator (`acc += rate; while acc >= hz { acc -= hz; .. }`). `TickRate::dt()` (a method, `1.0 / hz`) is for continuous dynamics only. `Tick + Ticks` wraps (`wrapping_add`); a `u32` lasts about 6.8 years at 20 Hz.

`TICK_RATE` is compiled into the `.wasm`, so changing it changes the sim identity. `tick_rate_hz` is stamped in every snapshot and segment header (`persist/identity.rs`) and a mismatch is treated like a `SCHEMA_VERSION` mismatch: the save loads only through `G::migrate` (no rescale helper exists; without a hook the result is `SaveIncompatible`). The UI never counts ticks itself: replicated state carries `done_at`, and `client.clock()` exposes the authoritative tick, the predicted tick and `ticksPerSecond` (client-role `Clocks` in `client/frame_view.rs`; the SAB clock block `clock-block.ts`). The client's estimators live in `clock/`: `HostClock` (a slewed, monotone "what tick is it now", at most 10% dilation, stepped only by `rebase()`) and `LeadEstimator` (median of the last 8 ack samples, clamped to 1..=40 ticks); the prediction model is in [sync-and-netcode.md](sync-and-netcode.md) and [0012](../decisions/0012-prediction-and-reconciliation.md).

## Randomness

`rng.rs` `SimRng`: hand-rolled PCG32 (integer only: `next_u32`, unbiased `below(bound)`, `fork(stream)`), plain `Codec` data. Its state is part of the snapshot, so replay and restore reproduce every draw. It is reachable only through `WorldWrite::rng()`, which is `Ok` on the host and `Err(Unknown)` under prediction (`Predicting::rng` marks the overlay unknown, so `?` makes the action `NotPredictable`). Never seed from anything but sim state; `on_player` in the reference game takes `rng()` with `let Ok(..) else`. Worldgen uses stateless coordinate hashes only ([world-and-worldgen.md](world-and-worldgen.md)). The `rand` crate is not used.

## Determinism rules for sim code

Rules, measurements and enforcement: [0002](../decisions/0002-determinism-same-wasm-everywhere.md), amended by [0068](../decisions/0068-phase-3-decisions-testing-and-tooling.md) §1 (x86-64 closed: native, Node, Bun, Chromium, WebKit and Firefox matched the same goldens). The path-scoped checklist that loads when you read sim code is [determinism.md](../../.claude/rules/determinism.md); do not restate it here. Points that bite in this subsystem:

- **`HashMap` and `HashSet` are clippy-disallowed** in the engine crate, every fixture and every game crate: `disallowed-types` in the root `clippy.toml` (lines for `std::collections::HashMap` / `HashSet`), set to `deny` by `[workspace.lints.clippy]` in the root `Cargo.toml`, and reached by each crate's `[lints] workspace = true` (the engine crate repeats the two `deny` lines in its own `[lints.clippy]`, which `exports-map` keeps in step because the shipped manifest cannot use `workspace = true`). Use a sorted `Vec`, `BTreeMap`/`BTreeSet`, or an engine arena. The same file bans std float transcendentals via `disallowed-methods`. `pnpm lint` runs it.
- Time is the tick counter. No wall clock, I/O or ambient input in Rust; `engine.*` is the whole import allowlist ([0014](../decisions/0014-js-wasm-boundary.md)).
- Everything that runs in the deterministic core (`Sim`, `Authority`, `budget`) must not import the host role; `tests/module_layering.rs` enforces it. That is why `budget` lives at `crate::budget`, not under `host/`: live host, replay and recovery all call `Sim::step`.
- `admit`, rate limits, pacing, subscriptions, presence and everything in `ClientSide` are outside the core: they may use non-sim state but must never feed a write.
- A change to `G::Action`'s layout is a `SCHEMA_VERSION` bump: postcard is not self-describing, so old log bytes could decode as a different valid action ([0024](../decisions/0024-planning-amendments.md) §3).
- Changing the toolchain, a dependency or a flag produces a new `.wasm` hash and so a new log segment ([persistence.md](persistence.md)).
