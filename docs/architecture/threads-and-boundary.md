# Threads and the JS/WASM boundary

The engine runs as shared-nothing actors: one compiled `.wasm`, instantiated once per role in its own worker (or once on a server), with a fixed numbers-only `extern "C"` ABI between each instance and its JS shell. Threads talk through preallocated `SharedArrayBuffer` structures. The main thread runs no WASM and does only DOM, input, camera, GPU calls and polling. Code: Rust ABI in `packages/engine/crates/engine/src/abi/`; TypeScript in `packages/engine/src/` (`abi.ts`, `loader.ts`, `client.ts`, `worker.ts`, `worker/`, `sab/`, `ring-connection.ts`, `clock-block.ts`, `frame-loop.ts`, `support.ts`). Why: [0014](../decisions/0014-js-wasm-boundary.md), [0015](../decisions/0015-threads-memory-and-topology.md), [0016](../decisions/0016-zero-gc-definition.md), [0067](../decisions/0067-phase-3-decisions-runtime-packaging-hosting.md).

## Topology

`createClient` (`client.ts`) compiles the module once (`compileStreaming`), allocates every SAB (`createSabSet`, `sab/layout.ts`), spawns the workers (no nested workers) and posts each a `setup` message with the `Module`, the SABs and its config. One script hosts every kind: `worker.ts`'s `run()` dispatches on `SetupMessage.kind` to `worker/{client,sim,gen,net}.ts`. `worker-auto.ts` is the zero-config entry; a game may supply its own two-line worker (see [runtime-and-hosting](runtime-and-hosting.md)).

| Thread | WASM role | Does |
|---|---|---|
| main | none | rAF `frame-loop.ts`, camera/input writes, upload and render, UI/clock reads, `dispatch` |
| client worker | `Client` | replica, prediction, `extract`, draw list, all uplink assembly; its loop is the frame clock |
| sim worker (single-player) | `Sim` | authoritative world, tick loop, persistence; same `SimHost` code as the server |
| net worker (multiplayer) | none | `WebSocket` byte pump between the uplink/downlink rings and the socket; never parses a frame |
| gen workers (1, or 2 when `hardwareConcurrency >= 8`; `genWorkerCount`, `MAX_GEN_WORKERS`) | `Gen` | chunk generation: request ring in, result slab out |

The client worker cannot tell single-player from multiplayer: the same frame bytes arrive on the downlink ring, from the sim worker's `RingConnection` or from the net worker. On a server there is one JS context, one `Sim` instance, no workers or SABs (`server.ts`, `SimHost`; never import `node:` or DOM there). Protocol and sessions: [sync-and-netcode](sync-and-netcode.md); gen queue: [world-and-worldgen](world-and-worldgen.md).

Setup messages, `ready`, `fatal`, `stop` and the test-only `test-call` are the only `postMessage` traffic (`worker/protocol.ts`); none in steady state. A `Module` the browser refuses to deserialise (`messageerror`, `DataCloneError`) makes `createClient` resend the setup with `wasmUrl` (`module-refused.ts`, [0067](../decisions/0067-phase-3-decisions-runtime-packaging-hosting.md) item 8).

## Cross-origin isolation

Mandatory for every game: `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` on every path and status code (the worker script itself needs COEP; a 304 without the headers made WebKit refuse the worker). `credentialless` is never used (WebKit ignores it). There is no `postMessage` fallback and no `coi-serviceworker`. `createClient` fails with a readable `EngineStartError` when `crossOriginIsolated` is false; `checkSupport()` (`support.ts`) reports `not-isolated`, `no-sab`, `no-module-worker`, `no-webgpu` and the rest by `code`. The Vite plugin (`vite.ts`) sets the headers for dev and preview. Header listings per host were never verified on a real static host ([0067](../decisions/0067-phase-3-decisions-runtime-packaging-hosting.md) item 1): see [runtime-and-hosting](runtime-and-hosting.md).

## SAB structures (`sab/`)

All fixed-size, created once, no `postMessage`. Sizes are `RING_DEFAULTS` and the `DRAWLIST_*` constants in `sab/layout.ts`; `sabBytesTotal()` assumes two gen workers.

- **`ControlBlock`** (`sab/control.ts`): one `Int32Array` for all threads. Global words (`CB_*`: lifecycle, frame request, step-tick request, link state, profiling counters) then a block of `W_*` words per worker (`W_WAKE`, `W_YIELD`, `W_PARKED`, `W_READY`, `W_ACK`, `W_MEM_PAGES`, `W_MEM_GROWS`, `W_STATUS`) addressed by `workerWord(index, field)`. Worker indexes: `WORKER_CLIENT`, `WORKER_HOST` (sim or net), `WORKER_GEN0/1`. Words are appended, never renumbered. One wake word per consumer thread, not per ring ([0024](../decisions/0024-planning-amendments.md) §10).
- **SPSC ring** (`sab/ring.ts`): control words (head, tail, drops, pushed, popped), then slots with an 8-byte header; messages larger than a slot span slots, all or nothing. Head/tail are unbounded counts. Rings: `downlink`, `uplink`, `actionRing`, `inputRing`, `uiRing`, `uploadRing`, `genRequest[i]`, `genResult[i]`. Full-ring policy per ring ([0067](../decisions/0067-phase-3-decisions-runtime-packaging-hosting.md) item 12): backpressure for `downlink`, `uplink`, `uiRing`, `uploadRing`, gen rings; `dispatch` throws `engine: action queue full` on `actionRing`; `inputRing` drops and counts.
- **Seqlock** (`sab/seqlock.ts`): latest-wins small records. The camera block (`camera/block.ts`) and the clock block (`clock-block.ts`, eight `u32` fields: ticks, session state, seq seed, ack seq, tick fraction, revealed) use hand-rolled typed fields over one.
- **Triple buffer** (`sab/triple.ts`): the draw list, 1 KiB header + 2 MiB body per slot.

Wake protocol: a producer pushes, then `ControlBlock.wake(index)` (`Atomics.add` + `notify` on `W_WAKE`). A consumer worker loops in `runBlockingLoop` (`worker/shell.ts`): load `W_WAKE`, drain everything, `waitForWake(last, timeout)`. `Atomics.wait` is called only from `ControlBlock.waitForWake` (`sab.atomics_wait_confined`); `Atomics.waitAsync` is banned. Main never blocks: it polls rings once per rAF and wakes the client worker once per rAF after the camera write (the client's frame request, `CB_FRAME_REQ` against `W_ACK`; frames never queue). The sim worker waits with the timeout of `AtomicsTimer` (`worker/atomics-timer.ts`, [0030](../decisions/0030-sim-host-resync-based-pacing.md), [0032](../decisions/0032-atomics-timer-bounds-external-wakes.md)). The net worker is event-driven, never in `Atomics.wait`, and drains its uplink ring on a timer chain.

Park protocol: a blocked worker receives no events. `W_YIELD` makes it return to its event loop, then `W_PARKED` is set; `resume` re-enters the loop. Tests, shutdown and Promise-only APIs (OPFS) use it. A park request must bump and notify the waited word, and every blocking loop checks yield before its first wait ([hot-paths rule](../../.claude/rules/hot-paths.md)).

Client worker pumps in `worker/`, each built once at setup and run every wake from `client.ts`'s `body()`: `client-action.ts` (`actionRing` into `on_action`, `client_poll_ui` output onto `uiRing`), `client-input.ts` (`inputRing` into `on_input`), `client-gen.ts` (gen results in, gen requests out), `client-upload.ts` (stages `upload_stage` records onto `uploadRing`). Helpers: `gen-record.ts` (16-byte gen request/result header), `gc-hook.ts` (zero-GC negative controls via `CB_TEST_CONTROL`), `test-call.ts` (parked-only `test-call` channel), `test-trap.ts` (injects a trap for robustness tests).

`RingConnection` (`ring-connection.ts`) is the sim worker's `Connection` over a ring pair (`downlink` produced, `uplink` consumed), created at startup only when the setup message has `link: true`. `worker/client-net.ts` drains the downlink straight into `on_frame` and pushes `client_poll_uplink` output to the uplink; `worker/client-drawlist.ts` copies the draw list to the triple buffer. Ring-to-region copies move whole fixed buffers with `.set()` and carry the real length as a separate number (`lastMessageLength`, `frame.len`); details in `packages/engine/src/CLAUDE.md`.

## The ABI

Owner: `abi/registry.rs` (version, `Role`, `Status`, `RegionId`, the `Instance` trait, the extern list inside `export_instance!`); `abi.ts` mirrors it (`ABI_VERSION`, `ABI_EXPORTS` with role, arity and result kind) and `tests/wasm/abi-registry.test.ts` fails when they differ. `export_game!` is the only ABI line a game writes; it installs the extern list for all roles, the allocator and the panic hook. Adding to the ABI is one commit: extern + defaulted trait method, `ABI_EXPORTS` row, version bump in both; numbers are appended, never reused. The loader refuses a module whose `engine_abi_version()` differs (`AbiMismatchError`).

- **Numbers only**: `i32`/`u32`/`f32`/`f64`, at most one result; no strings, `i64` (two `u32` in a region), objects or closures. Result kinds: `status`, `len` (negative is `-(status)`), `ptr`, `u32`, `void`. A wrong-role call returns `Status.WrongRole` on every profile, no trap ([0024](../decisions/0024-planning-amendments.md) §16).
- **Imports**: exactly `engine.panic(ptr, len)` and `engine.log(level, ptr, len)`, output-only; text is decoded in the instance's own isolate by the loader ([0067](../decisions/0067-phase-3-decisions-runtime-packaging-hosting.md) item 10). A third, `engine.bench_mark`, exists only in `bench-phases` builds; the loader always supplies it as a no-op unless `setBenchMarkHook` is set ([0055](../decisions/0055-bench-only-phase-import.md)). `allowlist.test.ts` pins the shipped list.
- **Boot and regions**: `engine_boot` returns a fixed 64 KiB region (`BOOT_BYTES`); the loader writes the config JSON (`InstanceConfig`: `arenaBytes`, `arenaCeilingBytes`, `game`) at offset 0, `engine_init(role, len)` parses it, reserves the arena and lays out regions (`abi/regions.rs`). Panic text is formatted into the last `BOOT_TEXT_BYTES` without allocating. After init the loader reads each region's `(ptr, len)` once via `engine_region`/`engine_region_len` (`RegionId`: Rx, Tx, Result, DrawList, ChunkTexels, Ui, Persist, Camera, GenOut, GenIn, Downlink, Progress; a role lacks some). Regions never move or resize. `Result` is 64 bytes, for small multi-value outputs. Copy in, call with a length, copy out, always whole blocks through view pairs.
- **Panics**: `panic = "abort"`; the trap is caught in `call0/1/2`, the instance is marked `dead` (never called again), and `EngineTrap` carries the panic text. Recovery policy per role: [persistence](persistence.md), [sync-and-netcode](sync-and-netcode.md).

## Loader (`loader.ts`)

`instantiate(module, role, config)` returns an `EngineInstance`; it takes a `WebAssembly.Module` and works in a worker, Node, Bun and workerd, so there is no generated glue. Exports are called only through `call0/call1/call2` (fixed arity; dead check; trap capture; detach check). `memory.grow` detaches every view of a non-shared memory, so after each call the wrapper checks `ArrayBuffer.prototype.detached` (feature-detected once at load, not `byteLength`, which boxes a number) and rebuilds `inst.mem` and every `RegionView.u8`, then runs `onViewsRebuilt` callbacks. Read `inst.mem` and `region(id).u8` every time; never cache them. `worker/instantiate.ts` wraps it for workers: `instantiateFactoryForSetup` (a fresh instance per call, for persistence restore candidates) and publishing `W_MEM_PAGES`/`W_MEM_GROWS` so main reads memory by polling, not messages.

## Memory

No WASM threads and no shared WASM memory (stable Rust; `atomics` is nightly), so every cross-thread byte is copied twice by `TypedArray.set` between views made at init. Each instance has a fixed arena: `engine_init` allocates and frees one block of `arenaBytes`, which makes std's allocator do the single `memory.grow` (`abi/arena.rs`, `Arena` wraps `System`, installed by `export_instance!`; [0067](../decisions/0067-phase-3-decisions-runtime-packaging-hosting.md) item 11). The module declares no `maximum` (iOS failure). Defaults (`DEFAULT_ARENA_BYTES` in `client.ts`): sim 96 MiB (64 MiB world budget + slack), client 48 MiB, gen 4 MiB each. `engine_init` returns `BudgetExceedsArena` if the world budgets do not fit; `createClient` rejects (`EngineStartError` `arena-config`, `checkArenaBudget`, test `arena.sum_rule`) a topology whose arenas plus `sabBytesTotal()` plus a 20 MiB GPU share pass the 256 MiB whole-tab target of the baseline phone (iPhone 12-class / 4 GB Android; per-instance ceiling 256 MiB, `DEFAULT_CEILING_BYTES`). Growth past the reservation traps in dev builds; release builds grow in 16 MiB steps to the ceiling and count it in `engine_mem_grows()` (`memGrows()`); steady state expects 0. Memory never shrinks; leaving a world drops the instance. A device pass proves the reservation instantiates, not that every page was committed ([0067](../decisions/0067-phase-3-decisions-runtime-packaging-hosting.md) item 14).

**There is no ABI export for live arena bytes.** `abi::arena::live_bytes()`/`high_water_bytes()` exist for native Rust tests only (`no_alloc_terrain`, `games/reference/sim/tests/bench_high_water.rs`). Because the arena is reserved up front, `memory.buffer.byteLength` is constant at every world size and detects nothing alone. Soaks therefore use a tight `arenaBytes`, so that a leak traps (dev) or grows (release) before the end, plus a constant `byteLength` and `memGrows() === 0`:

- `soak-netcode @slow` (`games/reference/tests/netcode/soak.test.ts`, suite `netcode`): `SOAK_ARENA_BYTES` = 8 MiB over a live set under 5 MiB; asserts `grows` 0 and `memoryBytes` identical from minute 5 on, 30 virtual minutes.
- `highwater-large-save @slow` (`tests/wasm/large-save-memory.test.ts`, suite `wasm`): finds the peak as the smallest `arenaBytes` with zero grows; an arena 8 MiB under it must grow, so the check is not vacuous.
- `soak-browser @slow` (`tests/browser/gc-reference-soak.spec.ts`, suite `browser`): `byteLength` unchanged and `engine_mem_grows` 0 on every WASM instance over 24,000 ticks, but with the page's default arenas, so on its own it is a weak leak detector.

A new soak must pick an arena a small leak can exhaust.

## Hot-path rules here

The full list is [`.claude/rules/hot-paths.md`](../../.claude/rules/hot-paths.md); verified by the `gc-test` skill ([`SKILL.md`](../../.claude/skills/gc-test/SKILL.md)) against `budgets.json`. In short: views and SAB descriptors are built in constructors; no `subarray`/`slice`/closures/`postMessage` per frame, tick or message (`sab/no-alloc-syntax.test.ts`); per-frame time comes from rAF's own timestamp or `createResyncingClock` (`clock.ts`), never a bare `clock.now()`; the client reads time from the camera block, not from the `frame(t_ms)` argument, which is ignored (a `Float64Array` read boxes a number). The server is outside the zero-GC budget.
