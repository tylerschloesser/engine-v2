# World and worldgen

The world is an infinite 2D tile grid split into chunks (default 32x32 tiles, `CHUNK_BITS = 5`). Terrain is not stored: it is a pure function of seed, params and chunk coordinate (the pristine function `P`). World state is only what actions changed: sparse per-chunk tile overlays plus a global entity store. Dense chunks are an invisible LRU cache of `P + overlay`. The game writes `P` (`Worldgen`); the engine decides where and when it runs (client gen workers, a synchronous call on a cache miss, a between-tick warmer on the host).

Rust (`packages/engine/crates/engine/src/`): `world/` (tiles, coordinates, overlays, cache, `TerrainStore`, trait tables), `worldgen.rs`, `noise.rs`, `gen_queue.rs`, `client/terrain_feed.rs`, `host/warm.rs`, `store/` (entities, per-chunk index), `client/upload.rs` (`Uploader`), `view.rs` (`lookahead_chunks`), `world_access.rs` (`WorldRead`/`WorldWrite`/`View`), `budget.rs`. TypeScript (`packages/engine/src/`): `worker/gen.ts`, `worker/client-gen.ts`, `worker/gen-record.ts`, `genWorkerCount` in `client.ts`. Reference game: `games/reference/sim/src/worldgen.rs` (`RefWorldgen`, `RefParams`), `games/reference/world.json` (seed and params).

## Model

- **Coordinates.** `TilePos {x, y: i32}`; `ChunkCoord = tile >> CHUNK_BITS` (floor); local index is row-major. `WorldPos` is Q24.8 fixed point in an `i32` per axis. The valid range is `TILE_MIN..=TILE_MAX` = +-2^23 tiles (about +-8.4 million) per axis. Out-of-range reads return `Tile::VOID`; `set_tile` returns `OutOfRange`; movement clamps (`WorldPos::clamped`). Chunk map keys are `u64` (`ChunkCoord::key`).
- **Chunk size is runtime `ChunkDims`** built from `Game::CHUNK_BITS` (4, 5 or 6), not a const generic ([0024](../decisions/0024-planning-amendments.md) §9). The browser topology (gen-result slots, upload records, page texture) supports 5 only and asserts it at init; 4 and 6 are tested natively.
- **`Tile(u32)`**: bytes `[base, resource, aux_lo, aux_hi]`. `base` and `resource` are engine-known 8-bit layers (0 = no resource); `aux` is opaque to the engine. A 32x32 slab is 4,096 bytes. A game needing more ids or bits needs a new ADR ([0007](../decisions/0007-world-model.md) §4).
- **`TerrainStore`** (`world/terrain.rs`) composes `P` (a boxed `PristineSource`), `Overlays` (`BTreeMap<u64, ChunkOverlay>`, world state) and `Cache` (`world/cache.rs`: pooled slabs, intrusive LRU, fixed-hasher open-addressing index; not state). `tile(&self)` is total and may generate: the cache sits in a `RefCell`, no reference into a slab escapes, bulk reads go through `copy_chunk`.
- **Canonical overlays.** An overlay never holds an entry equal to pristine; each entry caches the pristine value it replaced in a `Cell`, filled when the chunk is materialized. State is a function of the effective world, not of write history, and `modified_tiles` can fall. Snapshots, state hashes, per-chunk hashes and the wire carry overlays and entities, never pristine tiles (`write_canonical`, `StateHash`).
- **The cache is invisible to the sim.** Generation on a miss costs only wall-clock time. `testing::cache_matrix::assert_cache_invisible` replays one script at capacity 1, default and unlimited with generation pre-warmed in shuffled orders and requires equal hashes and reads. A new world-touching test script should go through it.
- **Entities are not stored in chunks.** `Store<G>` (`store/mod.rs`) holds `BTreeMap<EntityId, G::Entity>` plus players, `Global`, id counters, active lists and timers; host and replica mutate it only through `Store::apply(&Delta)`. Ids: `EntityId(u32)`, host-allocated by `WorldWrite::spawn` from `next_entity_id`, from 1, monotonic, never reused; bit 31 marks a client-local provisional id ([0022](../decisions/0022-entity-ids-and-provisional-ids.md)). Store layout is not state, so it can change without touching saves or goldens.
- **`ChunkIndex`** (`store/index.rs`): per chunk that has entities, an occupancy bitset, sorted `(index, EntityId)` and overlapping ids. Derived: never encoded or hashed; `Store::rebuild_indexes` must reach exactly what incremental maintenance reaches. A multi-tile entity is stored once (anchor = min corner, footprint from the prototype) and indexed in every chunk it overlaps (at most 4; footprint <= chunk size). Overlap is tolerated, not rejected: `entity_at` answers the lowest id, `entities_in` sees both ([0063](../decisions/0063-phase-3-decisions-world-and-simulation.md) §3).
- **Traits.** `TraitSet(u64)`; the game declares bit constants, the engine owns the mechanism. `Registry` (`world/traits.rs`) holds `base_traits[256]`, `resource_traits[256]`, per-prototype traits and footprints. `traits_at(pos)` = base | resource | occupant traits. Placement asks the tiles (`!traits_at(t).contains(NOT_BUILDABLE)`), naming no tile type. The client-role instance has the same tables, so ghosts and prediction run the same check. A resource under a furnace is "covered" by trait (`COVERS_RESOURCE`), not stored state ([0063](../decisions/0063-phase-3-decisions-world-and-simulation.md) §6).
- **What ticks.** Chunks never tick; entities do, via per-system active lists, sleep/wake and timers (see [simulation.md](simulation.md)). Everything that exists simulates, watched or not.

## Cap and budgets

The "max world size" is two budgets ([0007](../decisions/0007-world-model.md) §8). Coordinates are unbounded within the range; the cap applies to what is materialized.
- **Cache budget** (bytes, invisible): `cacheChunks`, default 1,024 chunks = 4 MiB (`DEFAULT_CACHE_CHUNKS`, `sim/mod.rs`; also defined in `game_instance.rs` and `testing/cache_matrix.rs`). On the host the `cacheChunks` config is read but not wired: the host `TerrainStore` uses the constant. The client instance reads it. Exploration only consumes cache, so it is never refused. `Replica::new` asserts the cache is at least the 144-chunk subscription cap and within `CLIENT_CACHE_BUDGET_BYTES` (4 MiB).
- **State budget** (deterministic counts in world params): `max_entities` 262,144, `max_modified_tiles` 1,048,576, `max_action_growth` 4 KiB. Nominal costs are engine constants (128 B per entity, 12 B per modified tile), never `size_of`. `budget.rs` runs the check in `Sim::step` before `Game::apply`, for game actions only (`StateBudgetFull`, also on id exhaustion); tick rules are never refused, so the budget is soft by that margin ([0023](../decisions/0023-action-growth-declaration.md), [0004](../decisions/0004-action-timing-and-rejection.md)). The 64 MiB-phone split check at init (real `size_of::<G::Entity>()`, `Status::BudgetExceedsArena`) runs only when a game sets `worldBudgetBytes`; the default is `u32::MAX`, a no-op, and the reference game sets none (`host/mod.rs`).
- Genesis writes are applied but not journalled, and genesis may arm timers with `wake_at` ([0046](../decisions/0046-genesis-writes-unlogged-and-timers.md)).

## Worldgen

- **`Worldgen`** (`worldgen.rs`): `type Params`, `const WORLDGEN_VERSION: u32`, `fn generate(seed, &params, chunk, out: &mut [Tile])`. No `&self`, no world handle, no RNG, no clock; it must write every element of `out`. Randomness only from `hash2(seed, x, y)` (stateless; never the sim PRNG). No neighbour reads: cross-border features come from a continuous noise field or a per-region hash each chunk evaluates alone. One chunk is single-threaded. v1 worldgen emits tiles only, no entities. It is sim-grade code under [determinism.md](../../.claude/rules/determinism.md) (the file lives under the rule's `paths`).
- **`noise.rs`**: optional f64 `simplex2` and `fbm2` a game may call; the reference game and `fixtures/worldgen` call only `fbm2`. Noise coordinates are f64 (f32 misclassifies about 1.4% of tiles near +-8M). Octaves, thresholds, biomes, scatter and tile art stay the game's. `RefParams` is `#[serde(default)]`, so `"worldgen": {}` in `world.json` uses defaults.
- **Adapters.** `Pristine<W>` adapts a game's `Worldgen` to the object-safe `PristineSource` the store calls on a miss. `GenCore<W>` is the `gen`-role wrapper behind the `gen_chunk` ABI export: one scratch slab reserved at `new`, writes `slab_bytes` of little-endian tiles, `Status::BadLength` otherwise.
- **Stamping.** World params, snapshots and log segment headers carry `WorldgenStamp {version, fingerprint}`. `worldgen_fingerprint` hashes the pristine tiles of 16 fixed chunks (`FINGERPRINT_CHUNKS`, near the origin and near +-2^18); the list is fixed forever. A mismatch on load takes the `SaveIncompatible` path (`persist/identity.rs`, [persistence.md](persistence.md)). Bump `WORLDGEN_VERSION` whenever `generate` output changes.
- **Seed and params** reach a client from `ClientSide::on_init` (local) or `Welcome` (remote): [0035](../decisions/0035-clientside-on-init.md), [0042](../decisions/0042-remote-client-world-config-from-welcome.md). Until `set_source` installs a pristine function, a remote client's `TerrainStore` is unconfigured and every read is `Unknown`. There is no map secrecy: worldgen code and seed ship to clients.

## Where generation runs

Clients regenerate pristine terrain; the host sends only overlays and entities ([0008](../decisions/0008-chunk-generation.md) §3, wire in [sync-and-netcode.md](sync-and-netcode.md)). Single-player uses the same path.
1. **Client gen workers.** The client instance owns a `GenQueue` (`gen_queue.rs`) wrapped by `TerrainFeed` (`client/terrain_feed.rs`). Each `frame`, `TerrainFeed::on_frame` reprioritizes from the camera; the ABI exports `gen_take`/`gen_deliver` move 16-byte request records (`[cx i32][cy i32][0][0]`) and results (header + slab). `worker/client-gen.ts` pumps them over SAB rings after `frame` on every client-worker wake (claim a ring slot first, then `gen_take`); `worker/gen.ts` runs `gen_chunk` in a `Role.Gen` instance with a tiny arena. Worker count: `genWorkerCount(hardwareConcurrency, requested?)`, 2 when `hardwareConcurrency >= 8` else 1, clamped to `[1, MAX_GEN_WORKERS]`; it affects latency only, never results. A gen-worker trap rebuilds the instance and retries; the same chunk trapping twice is fatal (worldgen is pure).
2. **Synchronous miss.** `TerrainStore::tile`/`materialize` calls `source.generate` inside the tick or the prediction read. Full-speed replay generates everything this way.
3. **Host warmer.** `host/warm.rs` `Warm` keeps one view rect per connection slot (`MAX_VIEWS` = 16) fed from the subscription machinery; `warm_one` materializes at most one uncached chunk nearest the view centre first. `server.ts` runs it in the idle gap for `WARM_BUDGET_MS` = 2. It may read subscriptions because the cache is invisible.

**`GenQueue`.** Priority is ring class (visible, ring 1, ring 2) then distance to the look-ahead point `centre + velocity * 0.5 s`, all integer (Q24.8). Generation covers `visible.expanded(2)` plus up to 2 look-ahead chunks treated as ring 1; retention (protection from LRU) extends to ring 3. At most 2 jobs in flight per worker; the array is preallocated (`MAX_PENDING` 512). Cancellation drops not-yet-dispatched entries outside ring 3; in-flight jobs are never cancelled and `complete` accepts late results. `set_view` also re-queues chunks whose cache content was invalidated, read from `TerrainStore::cache_invalidation_seq`.

**Delivery.** A worker result goes in via `TerrainStore::insert_pristine` (idempotent; a debug build asserts it equals the instance's own generation). The chunk is uploaded as pristine at once and patched when the host's chunk snapshot arrives (`replace_overlay`, which re-materializes a resident chunk synchronously, never leaving it non-resident). Until the snapshot arrives, prediction reads of that chunk are `Unknown`. Chunk leave frees the client's overlay and entities; the pristine cache survives. Upload to the GPU: [renderer.md](renderer.md).

## World access from games

`world_access.rs` defines `WorldRead<G>` (`tile`, `traits_at`, `entity_at`, `entity`, `entities_in`, `player`, `global`, `roster`, `tick`) and `WorldWrite<G>` (`set_tile`, `spawn`, `put_entity`, `despawn`, `put_player`, `put_global`, `rng`, `wake_at`), both object-safe; a handler compiles once against `&dyn WorldWrite<G>`. Implementors: `Authority` (host: reads total, writes infallible), `TickCx` (`authority.rs`, tick rules), `Migrating` (`migrate.rs`), `Predicting` (client, [sync-and-netcode.md](sync-and-netcode.md)) and read-only `View` (renderer, UI, shared helpers like `can_place`). Reads return `Result<_, Unknown>`.
- On a client replica `tile`, `traits_at` and `entities_in` are `Unknown` outside the held (subscribed) chunks; `entity(id)` is `Unknown` for a real id the replica does not hold ([0022](../decisions/0022-entity-ids-and-provisional-ids.md) §7). Callers use `?` and never default ([prediction.md](../../.claude/rules/prediction.md)).
- Actions name anything the sender may have predicted by tile (`entity_at`), not by id.
- `wake_at` panics outside genesis and tick rules.

## Gotchas

- `Worldgen::generate` must be total and pure for every `ChunkCoord` in range, including chunks at +-2^18 and the range edges; the worldgen golden covers 256 chunks including the edges.
- Never reach into a slab, hold a `Cache` borrow across a call that can materialize, or read the cache from a sim path in a way that depends on residency (`is_cached`, `slot_of` are for the uploader and queue only).
- Cache events are opt-in (`enable_cache_events`), enabled only where a store pairs with an `Uploader`; the host never drains them. `GenQueue` reads the scalar `cache_invalidation_seq` instead of draining, because two drainers in one `frame()` starve each other.
- Containers that are hashed or snapshotted are ordered (`BTreeMap`/sorted `Vec`); only the cache may use a fixed-hasher table. No `usize` in encoded state.
- `replace_overlay` generates synchronously for a resident chunk; a worldgen near `worldgenMsPerChunkWarn` (0.25 ms in `budgets.json`) makes a large join burst expensive ([0063](../decisions/0063-phase-3-decisions-world-and-simulation.md) §5). The only coded threshold is `worldgenMsPerChunkWarn`; the 1 ms per chunk baseline-phone budget is recorded in [0062](../decisions/0062-budgets-as-measured-at-phase-3-exit.md), not enforced in code.
- Per-frame and per-tick paths here (`GenQueue`, `TerrainFeed`, `Warm`, store reads) do not allocate: [hot-paths.md](../../.claude/rules/hot-paths.md); `tests/no_alloc_terrain.rs`, `no_alloc_gen_queue.rs`, `no_alloc_store.rs` police it.
- Overlay-to-dense promotion, area effects and a sampled client/server pristine-hash check are deliberately not built ([0063](../decisions/0063-phase-3-decisions-world-and-simulation.md) §1-2).
