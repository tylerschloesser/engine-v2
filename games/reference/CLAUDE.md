# games/reference

The reference game (rules and scope: `README.md` "The game"): a private Vite app plus `sim/`, a game crate on the engine's `Game` trait (`docs/decisions/0003-game-facing-api.md`).

## Module layout (`sim/src`)

- `content.rs`: terrain/resource ids, `TraitSet` bits, durations, `SEED` (every real page's seed -- `ClientSide` gets no engine seed/params channel), `Game::register`.
- `noise.rs`/`worldgen.rs`: `engine::noise` composition, `RefWorldgen`/`hash2` scatter, `terrain_at`.
- `rules/`: one file per feature (`collect.rs`: `StartCollect`/`CancelCollect`, `in_range`, `admit`; collects are not reservations (two players may collect one tile; the tile is re-read at completion and a gone resource ends with no item, keeping `apply` free of cross-player reads), and `done_at` is scanned from the player table in `tick`, not on the timer wheel; `craft.rs`: `StartCraft`, due-craft completion, `update_unlocks`; `place.rs`: `can_place`, `PlaceFurnace`; `furnace.rs`: deposit, take, pick-up, `advance`; `belt.rs`: `PlaceBelt`/`RotateBelt`/`PickUpBelt`; `belts/topology.rs` (M52): the belt-to-line mapping). `rules::tick` (`rules/mod.rs`) is the game's whole tick: collects, then the wakes drained once and dispatched by variant (furnace -> `furnace::advance`, belt -> `topology::on_wake`, `test-hooks`' request -> `topology::test_insert`).
- `client.rs` (`.claude/rules/hot-paths.md` applies): `ClientSide<RefGame>` (`RefClient`) -- the
  camera-follow spring, own-player circle/range-ring `extract`, `ui()` (below; `Ui.spawn` is
  `nearest_land_tile`'s one-time spiral, cached at construction), depletion visuals.
- `lib.rs`: the `Game` impl, plus wire-facing plain-data types (`RefAction`, `RefPlayer`, `RefUi`,
  `TileXY`/`WorldXY`/`UiCollecting`/`UiInRange`) instead of `engine::world`/`time` types.

## The `Ui` rule, DOM modules (`src/ui/`) and the two page entries (`src/`)

`Ui` changes at state-change rate, never per frame: `in_range`'s `from` is cached at tile-entry time (`tracked_range`: a real position within `RANGE` of its tile, `2 x RANGE` of the presence, far inside `admit`'s 16 tiles; a `ClientSide` stamping hook or a TS anchor-slot read (f32) were rejected); `spawn` never changes. A per-frame value never belongs in `Ui` (0003).

Framework-free (README). `dom.ts`: `el()`, `diffKeyed()` (generic keyed-list reconciler, reused
by M32-M34). `collect.ts`: one `<button data-collect-tile="x,y">` per `Ui.in_range` entry, anchored
with `client.overlay.anchor`; one CSS fill animation; `CancelCollect` on pan-out; a rejected
`StartCollect` adds a `reject-<reason>` class. `inventory.ts`: a fixed, non-anchored readout. Both
wired in `game.ts`'s `startGame` (the device/renderer/art/client/camera/UI wiring shared by `main.ts`,
`test-entry.ts` and `gc-entry.ts`), which also calls `client.camera.moveTo` to `Ui.spawn` once, only
when `shouldMoveToSpawn` (`src/spawn.ts`) allows it. **`Ui.in_range`/`world.tile()` need a real sim tick**, not
just `stepFrame` (`engine/test.stepTick`, safe on every topology, `gc-entry.ts`'s own connected one included -- `untilQuiescent` no longer
waits on `uploadRing`, a page's own job to drain). `tests/helpers/game.ts`'s
`panTo`/`uiState`/`clickCollect`/`pumpUntil` poll a real `uiState` condition, never a fixed count.

## Single-player vs invite mode (M34)

`src/mode.ts::selectHost`: no `#k=` in the URL fragment = a world of this browser's own (`world.json`: seed and worldgen, also `games/reference-server`'s default world); `#k=<joinKey>` (empty for an open server) = `{ kind: 'remote' }` on `wsUrl(location)`, the world comes from `Welcome`. Two players locally: `pnpm --filter reference build`, `pnpm --filter reference-server start`, `ENGINE_WS_PROXY_PORT=4174 pnpm --filter reference exec vite preview`, two browsers (not two tabs: the identity secret is per-origin `localStorage`, newest tab wins) on `http://127.0.0.1:4173/#k=`. `Ui.roster` (dots, `src/ui/roster.ts`), palette colours in `Global` (`content::PALETTE`, assigned with `SimRng` on join), remotes drawn in `extract`, `src/ui/status.ts` is the one place engine events are handled (M37): link line and `resyncing`, refused starts, storage (`durable: false` notice, storage line), `rendererLost` banner, `onFatal` screen, dev desync counter; `game.ts` registers each `client.on<Name>` before its first `await` (`onStorage`/`onResyncing` do not replay); a new event adds a `StatusUi` member, a registration and an audit row (`engine-events.test.ts`); test `status.spec.ts`: one `test.html?persist&flags=<TestFlags json>` page, hooks `__loseDevice`/`__corruptChunk`/`__statusLink`/`__showStartFailure`. A returning player's first `frame` seeds the spring from the presence `Welcome` carried and calls `cx.follow` once (the host keeps it: `detachKeepingPresence`); it moves the camera before `shouldMoveToSpawn` can, so the spawn rule never fights it. Persistence (M34b): `main.ts` starts the local world with `persist: true` (OPFS, snapshot on hide) and a refused start (`world-busy`, `save-incompatible`) shows `status.showStartFailure` (Export and Delete on `save-incompatible` only); `test.html` is in-memory unless `?persist[=worldId]` (reload, second tab, `__exportWorld`/`__importWorld`; reopen with a plain `goto`: the new sim worker waits for the old one's lock, 0050 §6), and `?maxEntities=n` caps the entity budget. Tests: `test.html?server=<ws>#k=` (`openGame(page, { invite: { server } })`, `startReferenceServer` in `tests/helpers/server.ts`, one browser context per player; `__stepTick` runs the server's ticks). `Client.onLink`/`onUi`/`onStorage`/`onResyncing` do not replay to late subscribers: register every `client.on<Name>` before the first `await` after `createClient` (`StartGameOptions.onClient`), and `.catch(() => {})` on `client.ready` so a refused start (`world-busy`) is no unhandled rejection.

## Conventions

- `TEST_SEED` (`sim/tests/common/mod.rs`) aliases `content::SEED`, also `src/main.ts`'s own world
  seed (a string literal there); `RefScenario` is the shared native test harness.
- A resource id doubles as its own "full" depletion-stage visual id; `tile_visual` adds a stage
  offset from `aux`. Three stage buckets only (10/10 -> 7/10 is still "full").
- Adding an item (M32): `ItemId` variant + `ITEM_COUNT` (`content.rs`), `ITEM_LABELS` (`src/ui/inventory.ts`), `ITEM` (`tests/helpers/game.ts`), bump `SCHEMA_VERSION`. A recipe: append to `RECIPES` (index = id = `unlocks` bit) and `RECIPE_NAMES` (`src/ui/craft.ts`). Tests reach states with `RefScenario::give` (native, never an action) or `collectN` (browser).
- Depends on `engine` alone (`reference_package_depends_only_on_engine`): never import across the
  package boundary from `packages/engine/tests/**`, even in `tests/` (one exception, from M34: `tests/helpers/server.ts` wraps `startTestServer`).
- Placement (M33): shared rule helpers take `&dyn WorldRead` and return `Result<_, Unknown>`; never name a tile or entity type in a placement rule (`can_place` asks `traits_at`; a new unbuildable terrain or building only adds `NOT_BUILDABLE` in `content::register`). A furnace may stand on a resource (R1, M39ai): the furnace prototype carries `COVERS_RESOURCE`, `traits_at` reports it for every footprint tile, `collect::collectable` refuses a covered tile (`StartCollect` -> `NoResource`; a due collect ends empty) and `RefClient::ui` drops it from `in_range`; derived, never stored. Every action is predicted, `FurnaceTake` included (R2); the engine's opt-out has fixture-only coverage. The game UI always has an `Export world` button (`src/ui/export.ts`, R4). Construction mode is client-local: `client.input.emit(LOCAL.PLACE_MODE, on)` (`src/ui/build.ts`, mirrors `content::local`) -> `RefClient.placing` -> ghost in `extract`. Step one frame after an emit or a dispatch before a tick waits (the rings drain in frames; the uplink is paced at 50 ms). A page draws its DrawList (circle, ring, furnace, ghost) with `engine/render`'s `attachClientDrawables(client, device, renderer, { colorFormat })`, called in `game.ts`; it loads `ClientOptions.assets.sprites` itself, and a hand-rolled frame loop must call `client.pick.acquire()` before `renderer.draw` (`draws.spec.ts` compares pixels with the pass on and off through `__pixelAt`; `__draws` reads the DrawList).
- Furnace (M33b): machines sleep. Change a machine's state only in `advance` (`rules/furnace.rs`), one put per state change, scheduled with `wake_at`; an idle machine has no timer and is never visited (`idle_furnaces_cost_nothing`). Actions address a machine by any footprint tile, resolved with `entity_at` (0022 section 6). Client state that points at an entity is keyed by tile and re-checked with `entity_at` every `frame`: entities can disappear (`RefClient.open`, `recheck_open`: read through the overlay-merged `FrameView::entities` when the tile is visible, since `FrameView::world()` is the raw replica; `Unknown` leaves it open). A tap finds its furnace by `ev.tile`, not `pick_id` (sprites are pickable since M33d, but a tile needs no pick record and survives the ghost-to-real swap). The panel (`src/ui/furnace.ts`) holds no open/closed state: it shows `Ui.furnace`. A panel's controls must not sit under a `.collect-button` in browser tests: stand out of collect range. Rule choices: fuel is lit at smelt start and ore consumed at smelt end (an interrupted world never loses ore); coal burns before wood; "empty" includes `burn_left`, so a furnace with lit fuel cannot be picked up; slot cap 999 rejects overflow and `advance` starts no smelt while `ingots_out >= 999` (it had destroyed ore against a saturated `u16`).
- Belts (M51, README "Belts"): `RefEntity` is an enum (`Furnace`, `Belt`); every entity site matches the variant (`furnace_at` refuses a belt `NoFurnaceHere`, `advance` skips belts). A `Belt` is one tile (`BELT_PROTO`, `NOT_BUILDABLE`; a splitter two, below), plain data (`dir`, `kind`, derived `shape`, per-lane `spawn`), never moved (rotate is a put with the same id and anchor, 0079 §20 (b)). `PlaceBelt`/`RotateBelt`/`PickUpBelt` (`rules/belt.rs`) are free and tile-addressed; placement is `can_place(w, origin, footprint, forbidden)` with `content::BELT_FORBIDS` (`NOT_BUILDABLE | COLLECTABLE`: no belt on a resource) and `FURNACE_FORBIDS`. Tools: `LOCAL.PLACE_MODE`'s `a` is 0 off, 1 furnace, 2 belt, 3 spawner, 4 despawner, 5 splitter, 6 underground entrance, 7 exit; `LOCAL.ROTATE_TOOL` turns the direction; `Ui.placing` (any tool) and `Ui.tool` (`UiPlacing { tool, dir }`); only the furnace tool ends when no furnace is left. Belt sprites (`content::SPRITE_BELT_*`): east, south, north drawn, west = east + `FLIP_X` (a mirrored curve swaps side), `param` = frame on the item clock. Transport caps per site: `world.json` (so the local page, `test-entry.ts` and the server), the gc entries, `golden-record.mjs` and `refHarness` declare the recommended 32,768 / 262,144; so do the test hosts (`startReferenceServer`, and through `readWorldCaps` in `packages/engine/tests/support/reference-golden.ts` the engine-side reference scenarios); `pnpm device:serve`'s server reads `world.json` too (full caps, not the large save); the large-save bench (`src/bench.ts`, `benchWorldConfig`) declares none (no belts, and the caps would cost ~20 MiB of its arena budget); the soak 1,024 / 8,192 with its arena 9 MiB. Caps size memory and, since M52, decide whether belts are mapped: a world without them maps no line, so its hash differs from the same play with caps; a replay passes the world's caps (`full-game.json` records them, `fullGameParams`). Two worlds with enough caps hash alike. The UI (M51b, `src/ui/build.ts`): one palette row (`.build-palette`): `.build-button` is the furnace tool (shown while `Ui.can_build`, so the M33 specs drive it unchanged), `.tool-button[data-tool=belt|spawner|despawner]` always shown, `[data-build-rotate]` (and the `R` key, a DOM `keydown` by `code`) while a belt tool is on; the page keeps the tool it emitted and a copy of the direction, turned at its own emit and overwritten by each `Ui.tool.dir`; a 1x1 Confirm sits at `(x + 0.5, y + 1)`. A tap on a placed belt opens its popover (`src/ui/belt.ts`, `.belt-popover`, `[data-belt-rotate]`/`[data-belt-pickup]`): `RefClient.belt` is kept by tile like `open` (`recheck_belt`), reported as `Ui.belt`; a tap opens the furnace panel or the popover, never both, and a tool or `CLOSE_PANEL` closes either. Hooks `__dispatchPlaceBelt`/`__dispatchRotateBelt`/`__dispatchPickUpBelt`, `__draws`' `spriteId`; helpers `placeBelt`/`rotateBelt`/`pickUpBelt`/`pickTool`/`beltDraws`, `BELT`, `beltSprite`; script steps `placeBelt`/`rotateBelt`/`pickUpBelt` (`fullGame()`'s belt passage since M52; `beltScript()` ends on `BELT_SCRIPT_HASH`, pinned by the headless `reference_belt_script_headless` and met by `reference_belt_script_dom`: a belt change re-pins it); tests `belt-construction.spec.ts`, native `belt_tap_opens_and_closes`. Topology (M52, `rules/belts/topology.rs`, its module doc has the rules): the tick maps every woken belt and its four neighbours onto transport lines (one line per lane per straight run, a curve its own 106/295 pair, side-loads `Merge` at +64/+192, the edge rule keeping east/south front points inside the tile); `apply` never writes transport, but `PlaceBelt`/`RotateBelt` write the edited tile's shape (`shape_of_kind`, reads only) and `PickUpBelt` puts `removing: true` (a despawn wakes nothing; the tick unmaps and despawns it the same tick; a removing belt draws nothing, takes no tap or action and still occupies its tile). Lane 0 is the belt's left seen along `dir`, lane 1 its right; `lanes_at(tr, tile)` reads a tile's lanes back from the tile index (the entity stores no line id). A rotation destroys the tile's items (question 10 default). Runs stop at `MAX_LINE_TILES` (4,096 tiles: the next tile starts a new run, linked by `Next`); at a full line cap a pair is mapped whole or not at all (`topology::belts_unmapped`). `PlaceBelt`/`RotateBelt` read the three neighbour tiles, so at the edge of the held chunks they are `NotPredictable`. Tests: `sim/tests/topology.rs` (and `RefScenario::assert_topology`, the from-scratch check), `topology_items.rs` (`#![cfg(feature = "test-hooks")]`: run by the `rust` suite's slow-tier `test-hooks` leg, `pnpm test:slow rust`, or `cargo nextest run -p reference-sim --features test-hooks --test topology_items`; items reach a line only through `RefAction::TestInsertItem`, which spawns a one-tick `RefEntity::TestRequest`, both appended last and behind the feature), netcode `belt-topology.test.ts`; `fullGame()` ends with a belt passage. Spawners and despawners (M53b, the module doc): `SetSpawner { at, lane, item, rate }` (one put of `Belt.spawn[lane]`, `rate` indexing `content::SPAWN_RATES`, `item == content::SPAWN_OFF` clears) and the tick re-sets both lane lines' engine schedules (`set_spawner`, 0079 §21) on the spawner's wake and whenever `reform` (re)creates its lines, a neighbour's wake included (the unchanged lane loses at most one period of credit); a refused `set_spawner` counts in `topology::spawners_unscheduled`; nothing is written per insert (`spawner_writes_nothing_per_insert`). The game's rules: a spawner accepts no input, is always straight and joins no run (its own line pair, linked by its output); a despawner feeds nothing, its lines end in `Output::Sink`, and it joins no run in front. The oracle `assert_topology` checks both and every scheduled lane. Splitters (M54, the module doc): `BeltKind::Splitter`, the one 2x1 kind, prototypes `SPLITTER_PROTO_EW` (2, 1 x 2) and `SPLITTER_PROTO_NS` (3, 2 x 1) picked by `dir` (`content::belt_footprint`), anchored at the footprint's min corner, halves left/right along `dir` from `topology::splitter_halves`; `RotateBelt` turns one 180 degrees in place (question 12's default: the footprint never moves; the axis changes only by pick-up and re-place); per half and lane an input line (midline to back edge) and an output line (front edge to midline), 128 each, read back by `splitter_lanes` (`input`/`output`), each input `Fork { a: left half's output lane k, b: right half's }`; a belt behind a half feeds it `Next`, anything into a long side or its front dead-ends, a half's output feeds its front tile like a belt's and counts as its input; never joined or rescaled; the test hook's lanes 2 and 3 are a half's outputs. Two inputs sharing a blocked output starve one (question 11, measured in `splitter_two_inputs`). Sprites 22-24 (`SPRITE_SPLITTER`, after the items; west = east + `FLIP_X`); the ghost and `apply_tap` use the footprint; `build.ts`'s `FOOTPRINT` is keyed by tool and direction. Tests `sim/tests/splitter.rs`, `splitter.spec.ts`, netcode `reference_splitter_*`; `fullGame()`'s splitter passage (`SPLITTER_AT`, rows -23 and -22).
